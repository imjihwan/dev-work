# 변경 기록

## 영상 품질·생성 속도: 실측 도구와 프롬프트 자리표시 수정

- `scripts/bench_generation.py`(개발 도구)를 추가했다. 실제 GPU 로 생성 속도와 화질을 재되, 사용자의 ComfyUI·사진·결과물과 분리된 측정 전용 ComfyUI(다른 포트, `logs/bench/` 아래의 별도 입력·출력 폴더)에서 합성 사진·합성 문구로만 돌린다. 단계별 시간(텍스트 인코딩·스텝·디코드·저장), VRAM 최대·남은 RAM, 영상 지표, 눈으로 비교할 프레임·얼굴 묶음을 남긴다. 사용자의 ComfyUI 가 켜지면 하던 작업을 멈추고 물러난다. 쓰는 법과 결과는 [docs/PERFORMANCE.md](docs/PERFORMANCE.md).
- 제작 도우미가 대기 중인 작업의 최종 프롬프트를 통째로 바꿀 때 `{{face_side}}` 가 방향 낱말로 바뀌지 않고 그대로 모델에 들어가던 문제를 고쳤다. 등록할 때와 같은 규칙(그 작업에 재 둔 방향 → 사진 1을 다시 잼 → 기본값 right)으로 바꿔 넣고, 이력의 글은 자리표시를 그대로 둔다.

## 설치·모델 받기: 새 PC 에서 화면이 켜지지 않던 문제 등

- `setup.ps1` 의 화면 파일 복사 목록에 `production_chat.py` 가 빠져 있어, 새로 설치한 PC 에서는 화면 서버가 시작하지 못했다(`ModuleNotFoundError`). 목록에 넣었고, 복사 목록·배포 허용 목록이 실제 파일과 어긋나면 실패하는 테스트(`test_setup_manifest.py`)를 추가했다.
- `setup.ps1`: 화면 파일을 먼저 복사한 뒤 선택 기능용 CPU 검출 모델을 받는다. 이전에는 얼굴 검출 모델을 받지 못하면 화면 복사 전에 설치가 멈췄다. 인물 잘림 방지(기본 켜짐)에 필요한 인물 검출 모델도 함께 받는다. 두 모델은 받지 못해도 경고만 하고 설치를 마친다.
- `Complete-Models.ps1` 이 선택 모델까지 받던 것(`--all`, 자동으로 받는 것만 약 67GB)을 필수 모델만 확인하도록 바꿨다. 이전에는 직접 받아야 하는 선택 파일 때문에 필수 모델이 모두 있어도 실패로 끝났다. 선택 모델은 `-All`. README 의 설치 명령도 필수 모델만 받는 것으로 맞췄다.
- `get_models.py`: 출력을 파일·파이프로 돌린 한국어 Windows 에서 목록의 `—` 나 한자 파일 이름 때문에 멈추지 않는다. `--only` 에 없는 id 를 주면 아무것도 확인하지 않고 성공으로 끝나던 것을 오류로 바꿨다. 명세의 위치가 ComfyUI 폴더를 벗어나면 거절한다.
- ComfyUI 위치 규칙(`--comfy` → 프로젝트 안 `ComfyUI` → `%USERPROFILE%\ComfyUI`)을 `install_person_detector.py`·`install_queue_pause.py`·`install_local_translator.py`·`restart_backend.py` 에도 맞췄다. 이전에는 프로젝트 폴더만 기본값이라, ComfyUI 가 사용자 폴더에 있는 PC 에서 빈 `ComfyUI` 폴더를 만들고 그 뒤 다른 스크립트가 그 폴더를 설치본으로 잘못 골랐다. 이제 ComfyUI 가 없는 폴더에는 아무것도 만들지 않는다.
- `install_local_translator.py` 가 삭제된 2B 모델의 유무로 판단해 매번 프롬프트 도우미 모델(약 5GB)까지 받으러 가던 것을 고쳤다. 번역기가 쓰는 실행 파일만 준비한다(`install_prompt_helper.py --engine runtime`).
- `restart_backend.py`: ComfyUI 를 멈춘 뒤 `logs` 폴더가 없어 PID 기록에 실패하면 대기열 복원이 중단되던 문제를 고쳤다(`start_comfyui.bat` 으로 켠 경우 `logs` 폴더가 없다).
- 소스 배포 허용 목록에서 빠져 있던 파일 8개(`.gitattributes`, PERFORMANCE·TROUBLESHOOTING 문서, 테스트 5개)를 넣었고, 공개 템플릿 검사가 프롬프트가 겹쳐 저장되는 칸을 모두 확인한다.
- 이 묶음은 스크립트를 실제로 실행해 설치·다운로드하지 않고, 구문 분석과 합성 파일 테스트로만 확인했다.

## 성능: 대기열이 클 때의 조회 부하, 화면 로딩, 창 사이 동기화

- 화면이 작업 상태를 물을 때마다 ComfyUI 의 전체 대기열(작업 그래프 포함, 대기 1,000건이면 약 8.9MB)을 다시 받던 것을 고쳤다. 표시용 조회(상태·이력·갤러리 진행률)는 그래프가 없는 작업 목록으로 받아 1초 동안 나눠 쓰고, 대기·실행 중인 작업에는 이력을 따로 묻지 않는다. 이 서버가 대기열을 바꾸면(등록·삭제·중지) 바로 다음 조회가 새로 받는다. 작업 목록 API 가 없는 ComfyUI 에서는 `/queue` 를 1초 동안 나눠 쓴다.
- 화면은 추적 중인 작업을 한 번의 요청(`/api/status?ids=…`)으로 묻는다. 이전에는 작업마다 따로 물어, 20건이면 2초마다 요청 20개를 차례로 보냈다(휴대폰·원격 접속에서 한 바퀴가 길어지는 원인).
- 합성 측정(가짜 ComfyUI, 20초): 대기 1,000건·화면 3개에서 ComfyUI 로 간 데이터 372.9MB → 1.6MB, 화면 서버 CPU 3.72초 → 0.27초. 대기 20건·화면 2개에서는 요청 812회 → 10회. 조건과 표는 [PERFORMANCE](docs/PERFORMANCE.md). 실제 영상 생성 시간에 미치는 영향은 재지 않았다.
- 상태 요청이 실패한 바퀴(화면 서버 재시작·연결 끊김·오류 응답)를 '작업을 찾을 수 없음' 횟수로 세지 않는다. 이전에는 화면 서버를 다시 켜는 10초 남짓 사이에 추적 중인 작업이 모두 실패로 표시될 수 있었다. 큰 묶음에서 사라진 작업은 함께 물은 것끼리 같이 정리한다.
- 화면 파일(HTML·스크립트)과 글 위주의 응답을 gzip 으로 보낸다. 일반 화면을 여는 데 받는 양이 약 300KB → 87KB.
- 창 사이 동기화: 받아 오기를 한 번에 하나만 한다(사진이 실린 수 MB 응답을 느린 연결에서 겹쳐 받던 문제). 요청을 보낸 뒤 이 창이 올린 내용을 늦게 도착한 예전 응답이 되돌리지 않는다.
- `scripts/dev_sandbox.py`: 가짜 ComfyUI 와 화면 서버 사본을 임시 폴더·임시 포트에 띄운다. 합성 데이터로 화면을 확인하거나(`--pending 300`) 조회 부하를 잴 때(`--measure`) 쓴다. 실제 ComfyUI·설치본·사용자 데이터에는 접근하지 않는다.

## 도우미·대화·이어 만들기·갤러리: 멈춤과 저장 실패 수정

- 프롬프트 도우미·제작 도우미가 예상하지 못한 오류를 만나면 '작성 중' 상태로 남아, 화면 서버를 다시 켤 때까지 다음 요청과 번역이 막히던 문제를 고쳤다. 어떤 오류든 작업을 오류 상태로 끝낸다.
- Grok 초안을 만든 뒤 검토 단계가 시간 초과되면 완성된 초안까지 버리던 문제를 고쳤다. 초안은 유지하고 검토만 '완료하지 못함'으로 표시한다.
- 공유 대화·이어 만들기 프로젝트·갤러리 상태 파일 저장도 Windows 의 짧은 파일 잠금에 다시 시도한다(전체 테스트에서 같은 원인의 간헐 실패를 3회 관찰). 대화 저장이 끝내 실패해도 다음 요청이 '다른 기기에서 처리 중'으로 막히지 않고, 진행 표시나 실행 기록을 쓰지 못한 것 때문에 요청·실행 단계가 실패로 바뀌지 않는다.
- 이어 만들기: 생성 중 진행률을 파일에 쓰지 못한 것만으로 그 편을 실패로 끝내지 않는다(ComfyUI 작업은 계속 돌고 있었다). 없는 프로젝트 번호에는 서버 경로가 담긴 원문 대신 "프로젝트를 찾을 수 없습니다."로 답한다.
- 갤러리: 상태 파일을 읽지 못한 것을 빈 상태로 보지 않는다. 이전에는 그 뒤의 저장이 즐겨찾기·휴지통 표시를 모두 지울 수 있었다. 깨진 파일은 보관하고, 잠긴 파일은 그 요청만 실패시킨다. 저장하지 못한 변경은 반영된 것처럼 남지 않는다.
- CPU 도우미·번역 모델의 준비 확인이 응답 지연 한 번으로 실패하지 않는다.
- 실제 Grok·CPU 모델 호출 없이 모의 응답과 임시 파일로만 검사했다.

## 화면 서버 견고성: 저장 파일 보호·거절 사유 표시·다른 사이트 요청 차단

- 상태 파일(이력·저장 설정·조합·모델 카드·화면 상태) 저장이 Windows 에서 간헐적으로 `PermissionError` 로 실패하던 문제를 고쳤다. 백신·색인 등이 파일을 잠깐 잡고 있는 순간 바꿔치기가 거절되는 경우로, 전체 테스트 약 22회 중 2회 재현됐다. 잠깐 다시 시도하고, 바꿔치기 전에 디스크까지 기록한다. 이전에는 작업이 ComfyUI 대기열에 들어간 뒤 이력 저장만 실패해 화면이 추적하지 못하는 작업이 생길 수 있었다.
- 저장 파일을 읽지 못한 경우를 '비어 있음'으로 취급하지 않는다. 이력·모델 카드·화면 상태 파일이 깨져 있으면 `<이름>.corrupt-<시각>.bak` 으로 보관한 뒤 빈 상태로 시작하고, 다른 프로그램에 잠겨 읽지 못하면 덮어쓰지 않도록 멈춘다. 저장 설정·모델 조합을 고치는 요청은 기존 파일을 읽지 못하면 덮어쓰지 않고 실패를 알린다. 목록 조회처럼 읽기만 하는 곳은 파일을 건드리지 않는다. 메모장으로 고쳐 BOM 이 붙은 파일도 읽는다. 모델 조합 저장·삭제가 겹쳐도 서로의 변경을 잃지 않는다.
- 작업을 ComfyUI 대기열에 넣은 뒤 이력 파일 저장만 끝내 실패한 경우 등록 실패로 답하지 않는다(다시 넣어 같은 작업이 두 번 생기지 않게). 항목은 메모리의 이력에 남아 다음 저장 때 기록된다.
- ComfyUI 가 작업을 거절한 경우(검증 실패 등) "ComfyUI(8188)에 연결할 수 없습니다" 대신 거절 사유(노드·값)를 보여 준다. 여러 편 등록 중 실패한 경우의 안내도 같다.
- 다른 웹 사이트가 브라우저를 통해 이 서버로 보낸 변경 요청(POST)을 거절한다. 요청의 `Origin` 이 화면을 연 주소와 다르면 403. 주소를 바꾸는 프록시 뒤에서는 `SIMPLEUI_TRUSTED_ORIGINS` 에 화면 주소를 적는다. 길이가 잘못됐거나 한도(`SIMPLEUI_MAX_BODY_MB`, 기본 1024)를 넘는 본문은 읽기 전에 거절한다.
- 영상 내려받기 이름에 한글이 있어도 내려받을 수 있고, 이름으로 응답 헤더를 바꿀 수 없다. 영상을 보내는 도중 실패하면 오류 문구를 영상 뒤에 덧붙이지 않고 연결을 닫는다. 화면에 보이는 파일 오류에는 서버의 전체 경로 대신 파일 이름만 싣는다.
- 시드에 0·음수·숫자가 아닌 값을 적으면 사진을 올리기 전에 거절한다. 0 은 시드 노드가 임의 값을 뽑아 이력에 적힌 시드로 재현되지 않았다. 비워 두면 지금처럼 랜덤이다.
- https 주소로 잘못 접속한 요청 등에서 기록 함수가 예외를 내던 문제와, 이력 목록 응답이 동시 수정과 겹칠 때 생길 수 있던 직렬화 오류를 고쳤다. 서버 기록에는 요청 주소의 경로만 남긴다(저장 설정 이름 같은 `?` 뒤의 값은 남기지 않는다).
- 길이가 모호한 POST(조각 전송, 길이 헤더 두 개)는 받지 않는다. `Expect: 100-continue` 를 쓰는 도구(curl·PowerShell)에도 오류 응답이 끝까지 전달된다.
- `scripts/run_tests.py` 로 파이썬·Node 테스트를 한 번에 돌릴 수 있다. 합성 데이터와 PC 내부 임시 포트만 쓰는 테스트 48개를 추가했다. 실제 영상 생성과 설치본 반영은 하지 않았다.

## 고급 설정 자동값: 모델에 맞춰 바뀜

- 고급 설정을 직접 고치지 않으면 모델 권장값을 따른다. 터보 euler·shift 7/4, 일반 25스텝·res_multistep·shift 11/4(DaSiWa 작성자 표의 범위 가운데). 직접 고친 칸만 유지하고 화면에 자동/직접 상태를 표시한다.
- 속도·품질 단계는 모델을 바꿔도 같은 단계로 옮긴다. 터보 LoRA 를 빼면 자동 스텝으로 돌아간다.
- 예전 일괄 기본값 10/3 이 모델 기본값·조합에 남아 있으면 지운다. 새 이력에 `shift_applied` 를 기록하고, 수정 전 이력의 불러오기·재생성은 실제로 쓰인 영상 shift 12 를 쓴다. 대기 항목 일괄 수정은 기록된 값을 그대로 쓴다.
- 실제 영상 품질 비교는 하지 않았다.

## Shift Video 가 영상 스케줄에 반영되도록 수정

- 스케줄러(`1512:2590`)가 shift 노드 앞 모델을 받아 영상 sigma 스케줄이 화면 값과 무관하게 H3 기본값 12 로 고정되던 문제를 고쳤다. 화면 값은 모델 내부 오디오 환산에만 쓰여 영상과 어긋나 있었다.
- 템플릿 연결을 shift 노드 뒤로 바꾸고, 서버도 생성 그래프마다 같은 연결을 강제한다(사용자 승인 예외). 이미 ComfyUI 대기열에 들어간 항목은 그대로이며, 현재 설정 대기 적용이나 다시 넣기로 새 연결이 적용된다.

## 일반 v5의 검증된 공개 미러 다운로드

- 화면 정리: 맨 위에 있던 대기열 추가·진행 상황을 모든 기기에서 화면 아래에 붙는 바로 옮기고(입력을 다 채운 자리에서 바로 누름), 영상 길이를 장면별 동작 옆으로, 화면비·화질·시드·반복과 사진마다 따로 만들기를 '4. 만들기' 칸으로 모았다. 핸드폰·아이패드(폭 900px 이하)는 만들기/작업 이력 전환을 넣어 이력을 찾으러 4,000px 넘게 내려가지 않게 했고, 핸드폰의 아래 바는 두 줄로 줄였다.
- '누가/무엇이 나오나' 칸 안내를 실제 동작에 맞췄다: 사진에 보이는 옷을 바꾸는 용도가 아니라(첫 장면 고정·유지 칸과 부딪침) 주인공 지정·안 보이는 몸·옷 채우기 같은 범용 규칙을 넣는 칸. 처음 예시에도 그 범용 문장을 넣었다.
