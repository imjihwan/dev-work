# 변경 기록

## 2026-11-17 (DutchIT CPU 메모리 보완)

- DutchIT의 키·값 캐시를 Q8_0으로 설정하고 CPU Flash Attention을 사용한다. 가중치 재배열의 모델 크기 추가 버퍼가 시작 중 메모리 보호 중지를 유발해 `--no-repack`을 적용했다. 가중치·8,192 문맥·두 스레드·GPU 레이어 0·8GiB 시작 및 2.5GiB 실행 제한은 유지한다.
- 기존 2B·번역기 옵션은 유지하고 DutchIT 전용 옵션을 회귀 검사한다. 실제 응답 검증에는 별도 합성 입력만 사용하며 작업 이력·사진·영상은 조회하지 않는다.
- 실제 합성 응답에서 길이를 벗어난 장면 시작 시각이 발견되어 DutchIT 새 초안의 시각을 영상 길이 안의 0.1초 단위로 JSON 문법에서 제한했다. 부분 수정의 원래 시각과 기존 2B 형식은 바꾸지 않는다.
- 합성 응답의 `camera smoothly pushes` 같은 중복 촬영 문구를 검사하도록 보완했다. 새 초안만 적용 전에 최대 한 번 다시 작성하고 검사하며, 기존 문장·부분 수정은 자동 재작성하지 않는다.
- 실제 8B CPU에서 합성 새 초안·검토(155.5초)와 음악만 부분 수정·검토(103.4초)를 확인했다. 성공 요청의 최대 작업 집합 5.07GiB·최소 여유 RAM 4.14GiB였고 종료 후 모델 프로세스가 해제됐다. 영상 생성 프로세스·대기열은 유지하고 개인 작업·사진·영상은 조회하지 않았다.

## 2026-11-17 (DutchIT CPU 프롬프트 도우미)

- 일반 화면·네 편 이어 만들기에 DutchIT H3 8B와 기존 2B 선택을 추가했다. DutchIT의 공개 지시문을 기존 편집기에 맞게 수정하고 기반 8B Q4_K_M을 CPU 두 스레드·GPU 레이어 0으로 실행한다. 사진은 전달하지 않는다.
- 기존 인물·유지 조건·카메라 칸과 저장 형식은 유지하며 설정·대기열 마이그레이션은 하지 않는다. 원테이크에서 새 컷, 새 촬영 지시, 없는 사진 참조를 검사하고 실제 채팅 토큰 한도 초과 시 잘라내지 않고 거절한다. 엔진 변경 후 이전 초안 적용도 차단한다.
- 8GiB 시작 여유·2.5GiB 실행 여유·900초 제한을 적용한다. 부족하면 명시적으로 거절하며 2B로 자동 대체하지 않는다. 설치 가중치 해시·원본 지시문 리비전·Apache 라이선스와 수정 내역을 기록하고 코드·가짜 DOM 회귀 검사를 추가했다.

## 2026-11-17 (갤러리 원본 썸네일 연결 보완)

- 갤러리만 열어 둔 경우에도 일반 생성 작업의 완료·원본 사진 연결을 갱신한다. 완료 상태가 먼저 기록되고 영상 연결이 늦게 도착한 경우도 보완하며, 오래된 미확인 항목이 새 완료 확인을 막지 않도록 순환 처리한다.
- 작업 이력 삭제 전에 원본 연결을 보존하고 저장 실패 시 재시도할 수 있게 한다. 빈 파일·잘린 WebP 캐시는 다시 생성한다.
- 썸네일이 표시되면 로딩 문구를 숨긴다. 일시적인 이미지 로딩 실패는 화면 근처 항목만 최대 3회 재시도하고 ↻로 다시 시도할 수 있다. 원본 연결이 없는 항목은 다른 사진이나 영상 프레임으로 추측 대체하지 않는다.

## 2026-11-17 (폴더 등록 인식·오류 안내 보완)

- MIME 형식이 비어 있거나 일반 파일로 전달된 JPEG/JFIF 등도 사진 확장자로 인식하고 전송 헤더를 보완한다. 폴더 수집은 모델 목록이 준비되기 전에도 가능하다.
- 등록 버튼이 비활성화되는 이유와 실제 등록 오류를 폴더 영역에 표시한다. 폴더 수집부터 실제 일괄 등록 함수까지 연결한 합성 회귀 검사를 추가했다.

## 2026-11-17 (폴더 사진 일괄 추가)

- 여러 폴더와 모든 하위 폴더의 사진을 모아 한 장당 작업 하나씩 등록할 수 있다. 폴더를 반복 선택하거나 PC에서 여러 폴더를 함께 끌어놓으며, 모은 사진 수를 확인한 뒤 명시적으로 등록한다.
- 폴더 확인에는 파일 핸들만 사용하고 등록 시 한 장씩 읽고 전송한다. 중복 선택·비이미지 파일 제외, 확인 취소, 읽기 실패 시 이전 목록 보존, 등록 완료 항목 제거와 미처리 항목 이어 추가를 지원한다. 참조 사진 묶음과 기존 대기열은 유지한다.

## 2026-11-17 (번역 품질 개선)

- 어색한 직역이 많던 Argos 번역을 교체했다. 기본 정밀 번역은 번역 전용 TranslateGemma 4B로 문맥·부정문·촬영 용어를 고려하며, 긴 글에는 QuickMT의 빠르게 방식을 선택할 수 있다. 프롬프트 작성 도우미의 모델은 유지한다.
- 정밀/빠르게 결과 캐시를 분리하고 참고 표기와 시간 코드 보존을 검사한다. 원문과 대기열은 수정하지 않으며 CPU 두 스레드·낮은 우선순위·RAM 제한·도우미 우선 처리를 유지한다.

## 2026-11-17 (내용 입력창 확대)

- 내용 칸의 글자·여백·기본 높이를 키웠다. 유지 조건·요약·소리·음악은 여러 줄로 확인할 수 있게 하고 장면 시각 칸의 폭을 줄여 동작 입력 공간을 확보했다. 기존 입력값과 설정 키는 유지한다.

## 2026-11-17 (로컬 번역 미리보기)

- 일반 입력 칸 아래에서 영문→한국어 번역을 확인하는 선택 기능을 추가했다. 입력을 멈추면 현재 칸만 번역하며 원문·생성 설정·대기열은 수정하지 않는다.
- 긴 입력은 문장·문단 경계로 나눠 순차 표시하고 메모리 캐시를 재사용한다. 선택 부분 번역, 이전 응답 무시, 참고 표기 보존과 실패 구간의 명시적 원문 표시를 지원한다.
- 약 121MB의 공개 번역 패키지와 별도 CPU 실행 환경을 설치한다. GPU 사용 없이 두 스레드·한 프로세스로 제한하며 프롬프트 도우미·낮은 RAM 상태를 우선한다. 설치 파일과 모델은 소스에서 제외한다.

## 2026-11-17 (갤러리 재생 정보 갱신)

- 갤러리 메타데이터가 바뀌어도 열린 재생 창의 LoRA 정보가 이전 상태에 남던 문제를 수정했다. 영상 ID별로 LoRA 정보만 갱신하고 재생 위치·소리·플레이어 요소는 유지한다.
- LoRA 기록이 없는 경우와 명시적으로 빈 목록인 경우를 구분하며, 일부·다중 재생에서 정보가 다른 영상과 섞이지 않는지 합성 데이터로 확인한다.

## 2026-11-17 (갤러리 고정 영역 축소)

- 갤러리에서 현재 작업 진행률만 상단에 고정한다. 필터·검색·정렬·선택 작업·안내 영역은 스크롤과 함께 올라가도록 분리하고 진행률 주변 여백을 줄였다.
- 아래로 스크롤하면 최상단 앱 메뉴도 숨겨 현재 작업만 남기고, 위로 스크롤하면 메뉴를 다시 표시한다. 작은 움직임·화면 크기 변화·스크롤 끝 반동을 구분하며 다른 탭으로 이동하거나 갤러리를 다시 불러오면 메뉴를 복원한다.

## 2026-11-16 (대기열 1순위 우선추가)

- 상단 일반 생성 버튼 옆에 `1순위 우선추가`를 추가했다. 실행 중인 작업을 중단하지 않고 새 작업을 대기열 맨 앞에 넣으며 기존 대기 항목끼리의 순서를 보존한다.
- 반복 생성은 연속 우선순위를 배정해 입력·시드 순서를 유지한다. 편집 중 우선추가는 막고, 중복 클릭·실패 뒤 버튼 복구와 일부 등록 성공 시 이력 보존을 합성 테스트로 확인한다.

## 2026-11-16 (원테이크와 초기 줌 조정)

- 원테이크 자동 문구에서 시작부터 카메라 구도를 고정하던 지시를 제거했다. 카메라 칸에 명시된 연속 이동·줌과 이후 정지를 허용하면서 컷·장면 재설정은 금지한다.
- 저장소 기본 예시의 카메라 문구도 필요한 경우에만 0.3~1초에 연속 줌으로 구도를 조정하고 이후 고정하도록 맞췄다.
- 유지 조건에 `no cuts`가 있어도 전체 연속성 문구를 생략하지 않는다. CPU 프롬프트 도우미도 원테이크를 고정 구도로 해석하지 않도록 맞췄다.
- 합성 입력으로 초기 줌 문구 보존, 시간별 동작의 컷 표기 제거, 다중 컷 모드 유지와 최종 프롬프트 갱신을 검증했다.

## 2026-11-16 (리뷰 후속 수정)

- 창 동기화 저장을 부분별로 직렬화하고, 충돌 응답은 요청 이후의 최신 입력까지 병합한다. 편집 중 도착한 응답은 편집 화면 대신 복원용 화면에 반영하며 미저장 변경은 다시 보낸다.
- 대기항목 불러오기와 복원을 최신 요청만 소유하게 해 연속 클릭 시 수정 대상과 화면 내용이 어긋나지 않도록 했다. 편집 종료 시 진행 중인 이전 읽기도 무효화한다.
- 한국어 등 다국어 요청에서는 영어 단어 대조만으로 요청 누락을 단정해 문장을 삭제하지 않는다. 원문을 유지하고 언어 간 대응을 확인하지 못했다는 검토 안내를 표시한다.

## 2026-11-16 (도우미 품질·얼굴인식강화)

- 프롬프트 도우미가 요청에 없는 옷·소품·장소를 지어내던 문제: 지시문의 물건 예시 제거, 분량 목표 축소·자동 상세 보강 끔, 요청에 없는 외모·소품·장소 단어를 코드로 빼고 검토 결과에 표시. 문장 전체가 아니라 그 단어가 든 구·절만 잘라 동작 문장은 남긴다(검토 결과에 뺀 부분 표시).
- 도우미 새 초안의 장면 시각이 앞쪽 0~2초에 몰리던 것을, 동작 분량에 맞춰 영상 전체에 다시 나눈다.
- 얼굴 방향 자동 판정: 프롬프트에 `{{face_side}}` 를 쓰면 등록할 때 사진 1의 얼굴(YuNet 눈·코끝)을 재서 `left`/`right` 로 바꿔 넣는다(코끝이 두 눈 가운데에서 눈 사이 거리의 0.06배 이상 치우치면 그쪽, 아니면 정면 → 오른쪽). 모델에게 뺨을 비교하게 하던 방식은 대부분 기본값(오른쪽)으로 가서 바꿨다. 순차 추가는 작업마다 자기 사진 1로, 대기항목 수정은 원래 사진으로 다시 잰다. 이력에는 자리표시 그대로의 프롬프트와 판정(`face_side`)을 남기고 설정 팝업에 보여 준다.
- 만들기 바를 화면 위(설정 묶음 줄 아래)에 붙였다: 사진만 바꿔 연달아 등록할 때 사진 칸 바로 위에서 누른다. 펼침 메뉴는 아래로 열린다.
- 창 동기화 덮어쓰기 막음: 뒤에 숨어 있던 창이 최신 상태를 받기 전에 무언가를 고치면 예전 화면 전체를 올려 다른 창의 변경(예: 투명 자전거 문장)을 지우던 문제. 올릴 때 마지막으로 맞춘 번호를 같이 보내 서버가 그 사이 바뀐 걸 알면 409로 거절하고, 창은 최신 상태 위에 자기가 바꾼 칸만 얹어 다시 올린다.
- 처음 예시를 투명인간처럼 보이지 않는 세발자전거·3/4 뷰 각도·앉은 자세 기준 구도 프롬프트로 갱신했다.
- 화면 재검토 반영: '남은 작업 모두 중지'·'현재 작업 재시작'에 확인 창을 넣고 아래 바의 ⋯ 메뉴로 떼어 냈다(제출 버튼 옆에서 잘못 누르면 대기 작업이 모두 빠지던 위험). 사진별 일괄 추가 두 버튼은 4번 칸 접힌 메뉴에서 아래 바의 '사진별로 추가 ▾'로 옮기고, 사진이 없을 때 안내를 '1번 칸에 사진을 먼저 올리세요'로 바꿨다(얼굴 크롭 안내는 얼굴인식강화일 때만). 설정 묶음 버튼은 화면 전체를 저장하므로 맨 위 줄로, 4번 칸 이름은 '출력·확인'으로, '유지할 것'은 '누가/무엇이 나오나' 아래로, 방식 선택은 사진 제목 아래로 옮겼다. 탭과 겹치던 제목 줄은 안내 한 줄로 줄였다.
- 화면 정리 4: 프롬프트 작성 도우미를 처음에는 접어 둔다.
- 화면 정리 3: 첫 탭 이름을 '영상 1편 만들기'로 바꾸고, 'LoRA 정보 표시'를 탭 줄 오른쪽으로 올렸다. 터치 기기에서는 이 PC의 탐색기를 여는 폴더 버튼을 숨기고 사진 칸 안내를 '눌러서 사진 고르기'로 바꿨다.
- 화면 정리 2: 칸마다 2~4줄이던 안내문을 한 줄로 줄이고, 이력 항목의 설정·프롬프트·삭제를 ⋯ 메뉴로 묶었다(삭제는 메뉴 맨 아래, 터치에서 버튼 40px 이상). 전체 대기항목 일괄수정은 대기 작업이 있을 때만 보조 버튼으로, 저장 이름은 '설정 묶음'과 '모델 조합'으로 나눴고, 핸드폰 장면 칸의 시각 칸을 줄여 동작 칸을 넓혔다.
- 화면 정리: 맨 위에 있던 대기열 추가·진행 상황을 모든 기기에서 화면 아래에 붙는 바로 옮기고(입력을 다 채운 자리에서 바로 누름), 영상 길이를 장면별 동작 옆으로, 화면비·화질·시드·반복과 사진마다 따로 만들기를 '4. 만들기' 칸으로 모았다. 핸드폰·아이패드(폭 900px 이하)는 만들기/작업 이력 전환을 넣어 이력을 찾으러 4,000px 넘게 내려가지 않게 했고, 핸드폰의 아래 바는 두 줄로 줄였다.
- '누가/무엇이 나오나' 칸 안내를 실제 동작에 맞췄다: 사진에 보이는 옷을 바꾸는 용도가 아니라(첫 장면 고정·유지 칸과 부딪침) 주인공 지정·안 보이는 몸·옷 채우기 같은 범용 규칙을 넣는 칸. 처음 예시에도 그 범용 문장을 넣었다.
- 처음 예시(서버에 화면 상태가 없을 때 쓰는 기본값)를 세발자전거 체크포인트 프롬프트(7초, 장면 0·1·2.6·3.4·4.4·6.2초)로 바꿨다.
- 창마다 브라우저에 따로 저장하던 화면 칸·설정·사진을 서버 한 곳에 두고 모든 창이 따라가게 했다. 다른 창이나 이력 불러오기·일괄수정이 남긴 값(길이·첫 장면 고정·시드)이 다른 창의 설정을 덮어쓰던 문제를 없앴다. 대기항목 수정·일괄수정 중 불러온 값은 공유하지 않고, 끝나면 들어가기 전 화면으로 돌아간다.
