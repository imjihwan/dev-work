# 화면 사용 안내

넓은 PC 화면의 오른쪽 채팅 패널(작은 화면에서는 오른쪽 아래 **제작 도우미 · Grok**)은 현재 입력·최종 프롬프트·대기열과 앱의 웹 기능을 다룬다. 대기 번호를 지정해 다른 항목을 조회·비교·수정할 수 있다. 기본은 변경안 실행 버튼으로 적용하며, 직접 요청한 변경의 자동 실행 옵션도 제공한다. 변경안과 실행 결과는 답변 아래 카드로 이어지고, 넓게/분할 보기/접기로 작업 화면과 오갈 수 있다. 대화는 PC 서버에 보관해 휴대폰·아이패드·LAN·Tailscale 주소에서도 같은 기록을 본다. 작성 중인 입력은 기기별로 유지한다. 다른 기기에서 불러온 변경안은 읽기 전용이며, **새 대화**는 모든 기기의 공통 대화를 초기화한다. [상세 사용법](PRODUCTION_ASSISTANT.md).

## 전체 대기항목의 내용 수정 확인

**전체 대기항목 일괄수정**으로 불러온 뒤 2번 내용·장면을 수정하고 상단 **전체 대기항목 수정 저장**을 누른다. 프롬프트만 바꾸려면 적용 범위에서 **내용**만 체크한다. 모델·LoRA, 화면·길이는 각각 체크한 경우 함께 적용된다. 실행 중인 항목은 수정 대상에서 제외한다.

저장 시 입력 칸과 수동 최종 문구의 기준을 다시 대조하므로 입력 이벤트가 누락되어도 새 2번 내용을 반영한다. 2번을 수정한 뒤 최종 문구를 직접 다시 편집했다면 그 최종 문구를 사용한다. 완료 안내의 **ComfyUI 반영 대조 확인**은 실제 큐의 실행 그래프까지 일치했다는 뜻이다. 영상 모델이 모든 동작 지시를 충족했다는 품질 판정은 아니다.

일부 실패 시 입력과 수정 모드를 유지한다. 전체 성공 또는 수정 취소 시에는 수정에 들어가기 전의 작성 화면으로 돌아가므로, 현재 입력 화면이 이전 문구로 보이는 것만으로 반영 실패를 판단하지 않는다. 적용한 항목의 불러오기에서 다시 확인할 수 있다. 대조 확인 실패의 원본 사본은 비공개 `queue-edit-recovery/`에 항목별로 보관한다.

## 브라우저별 기본 음소거

상단의 **기본 음소거**를 켜면 이후 여는 영상은 소리를 끈 상태로 시작한다. 갤러리와 이어 만들기 화면에서도 같은 설정을 바꿀 수 있다. 설정은 **이 브라우저의 접속 주소별로 저장**하므로 PC Chrome과 iPad Safari는 각각 선택할 수 있고, 같은 주소의 탭과 화면은 선택을 공유한다. LAN 주소와 Tailscale 주소는 별도로 기억한다. 저장소가 차단된 경우에는 현재 화면에서만 선택이 유지된다.

선택하지 않은 새 브라우저는 기존처럼 첫 영상 소리를 켠다. 설정을 바꿔도 생성 설정이나 영상 파일은 바뀌지 않는다. 영상 자체의 소리 버튼은 현재 재생에만 적용되며, 갤러리에서 이전·다음으로 넘길 때는 직접 조절한 음소거·음량을 이어간다. 이력의 자동 미리보기는 항상 음소거한다.

## 대기열을 보존하는 ComfyUI 재시작

화면만 고친 경우 `Restart-H3-UI.ps1`은 ComfyUI를 유지한다. GPU 메모리를 초기화하려는 **백엔드 재시작**은 진행 중 계산을 잃고 처음부터 다시 생성하므로 사용자 동의 후 실행한다. 보호 기능을 적용한 UI 서버에서 다음 명령을 사용한다.

```powershell
.\ComfyUI\.venv\Scripts\python.exe -X utf8 scripts/restart_backend.py
```

스크립트는 비공개 로컬 백업을 검증하고 상태 조회를 보류한 뒤 대기 작업을 분리한다. 실행 항목만 중단하고 ComfyUI를 다시 켜서 원래 ID·실행 데이터·클라이언트 정보를 복원한다. 진행 중이던 항목이 먼저, 나머지는 기존 상대 순서대로 등록된다. 화면의 입력 자동 저장은 유지하지만 복구 중 생성·편집·삭제 요청은 잠시 거절한다. 최종 개수·ID·순서·데이터 검증 후 보호를 해제한다.

실패 시 `backend-restart.tmp`와 `restart_backups/`를 유지해 자동 중복 제출을 막는다. 이 표식을 임의로 지우거나 일반 시작 명령을 반복하지 말고, 복원 완료 수와 백업을 기준으로 복구해야 한다. 백업에는 개인 입력과 참조 정보가 포함될 수 있으므로 열람·출력하거나 Git에 올리지 않는다. 백업은 그 시점의 사본이므로 과거 사본을 그대로 재실행하면 이미 끝난 항목이 중복 생성될 수 있다.

원래 백엔드가 살아 있고 재등록 전인 실패는 `--resume-backup <해당 백업 폴더>`로 이어갈 수 있다. 모든 항목의 재등록은 끝났고 최종 검증만 남은 경우에는 `--verify-restored-backup <해당 백업 폴더>`로 재검증한다. 후자는 새 작업을 제출하지 않는다. 내부 출력 대상 목록은 ComfyUI가 다시 검증하며 나열 순서를 바꿀 수 있어 같은 대상 집합인지 비교하고, 실제 작업 대기 순서는 별도로 엄격히 비교한다.

## 일반 영상과 대기열

**고급 설정(스텝·샘플러·스케줄러·영상/소리 shift)은 자동이 기본이다.** 직접 고치지 않은 칸은 고른 모델의 권장값을 따르고, 모델을 바꾸면 함께 바뀐다(터보 euler·shift 7/4, 일반 25스텝·res_multistep·shift 11/4 — DaSiWa 작성자 권장 범위의 가운데 값). 고급 설정 제목 옆에 `자동(모델 권장값)` 또는 `직접 지정: …`이 표시된다. 직접 고친 칸만 모델을 바꿔도 그대로 남고, 이때 권장값과 다르면 안내가 뜬다. `자동 값으로 되돌리기`로 모두 자동으로 돌린다. 속도·품질 버튼(빠르게/보통/품질)은 상위 설정이라 모델을 바꿔도 같은 단계로 옮겨 간다(터보 품질 8스텝 → 일반 품질 30스텝). `이 값을 이 모델의 기본값으로 저장`한 값은 그 모델의 자동 값이 된다. 조합·이력을 불러오면 모델 권장값과 다른 칸만 직접 지정으로 표시된다. 2026-11-23 shift 수정 전 이력은 실제로 쓰인 영상 shift 12로 불러오고 상세 정보에도 실제값을 함께 표시한다.

고급 설정의 **속도 우선**은 결과 영상이 기본과 달라지는 가속을 고르는 칸이다(기본은 `기본 — 결과 그대로`). `빠르게 — 희소 어텐션`은 어텐션에서 중요한 부분만 정확히 계산하고, `더 빠르게 — 희소 어텐션 + 스텝 캐시`는 변화가 작은 스텝의 계산을 건너뛰는 스텝 캐시를 함께 쓴다. 이때는 희소 어텐션이 문구·참조 사진·소리 부분을 따로 보호하지 못해 `빠르게`보다 결과가 더 달라질 수 있으므로 시안용이다. 같은 시드라도 기본과 다른 영상이 나오며, 실측 시간과 화질 비교는 [PERFORMANCE](PERFORMANCE.md)에 있다. 고른 방식은 작업과 함께 이력에 남고, 대기 항목 수정·일괄수정(모델 설정)·갤러리 재생성에도 따라간다. 필요한 노드가 없는 ComfyUI 에서는 고를 수 없다. 샘플러·스케줄러 칸 아래에는 H3 에 맞지 않는 선택(느린 샘플러, shift 를 따르지 않는 스케줄러)을 고르면 이유가 표시된다.

사진과 생성 설정을 고르고 내용을 작성한다. 장면별 동작을 바꾸면 자동 조립 프롬프트도 갱신된다. 최종 프롬프트를 직접 편집한 경우에는 직접 편집 상태를 별도로 관리하므로 제출 전에 최종 프롬프트를 확인한다. 이미 등록한 대기항목은 입력 화면의 변경만으로 바뀌지 않으며 해당 항목 수정 또는 일괄수정으로 저장한다.

화면 배치: 맨 위 줄에 설정 묶음 저장/불러오기, 그 아래 1 사진(방식 선택 포함) → 2 내용(누가/무엇이 나오나 → 유지할 것 → 요약 → 장면별 동작(옆에 영상 길이) → 장소·카메라 → 소리·음악) → 3 모델 → 4 출력·확인(화면비·화질·시드·반복, 최종 프롬프트) 순서다. 화면 위에 붙은 바에는 [대기열에 추가] [사진별로 추가 ▾(올린 사진을 번갈아 사진 1로 / 사진을 골라 한 장당 하나씩)] 진행 상황 [⋯ 작업 제어(현재 작업 재시작 / 남은 작업 모두 중지, 둘 다 확인 창)]와 수정 모드 안내가 모든 기기에서 붙어 있다. 폭 900px 이하(핸드폰·아이패드 세로)는 '만들기 / 작업 이력' 전환으로 한쪽만 보여 주고, 이력에서 불러오면 만들기로 돌아간다. 핸드폰에서는 아래 바를 버튼 한 줄 + 상태 두 줄로 줄인다. 이력 항목은 다운로드·수정·재시작·불러오기만 바로 보이고 설정·프롬프트·삭제는 ⋯ 메뉴(삭제는 맨 아래)에 있으며, 터치 화면에서는 버튼 높이를 40px 이상으로 키운다. 전체 대기항목 일괄수정은 대기 작업이 있을 때만 보조 버튼으로 나온다. 저장은 '설정 묶음'(사진·내용·모델·설정 전부, 이름 붙여 저장)과 '모델 조합'(모델·속도·LoRA만)으로 이름을 나눴다. 터치 기기(손가락 입력, 마우스 없음)에서는 이 PC의 탐색기를 여는 '결과 폴더 열기'·'모델 폴더'·'LoRA 폴더'를 숨기고, 사진 칸 안내를 '눌러서 사진 고르기'로 바꾼다. 'LoRA 정보 표시'는 맨 위 탭 줄 오른쪽에 있다.

화면 칸·설정·사진은 서버(`simple_ui/ui-state.json`, git 제외)에 하나만 두고 열려 있는 모든 창이 따라간다. 사용자 한 명이 여러 창을 오가며 쓰는 전제이며 마지막으로 고친 창이 기준이다. 창은 올릴 때 마지막으로 맞춘 번호를 같이 보내고, 그 사이 다른 창이 고쳤으면 서버가 거절(409)한다. 그러면 창은 최신 상태 위에 자기가 바꾼 칸(내용 칸·설정 하나하나, 장면 전체, 시드, 최종 프롬프트)만 얹어 다시 올리므로, 숨어 있던 창이 예전 화면 전체로 덮어쓰지 않는다. 이 창에서 고친 내용이 아직 올라가지 않았으면 다른 창 값으로 덮지 않는다. 숨겨진 창은 다시 볼 때 맞춘다. 대기항목 수정·일괄수정은 그 항목을 화면에 불러온 임시 상태라 공유 상태에 올리지 않고, 수정을 저장하거나 취소하면 들어가기 전 화면으로 돌아간다. 서버가 비어 있으면 처음 연 창의 상태로 시작한다.

`대기열 추가`는 현재 구성을 등록한다. `사진 순차적 대기열 추가`는 여러 참조 사진의 순서를 회전해 각각을 첫 사진으로 한 번씩 사용한다. `사진 개별 대기열 추가`는 선택한 사진마다 개별 항목을 만들며 100장 제한이 없다. 다만 브라우저·PC의 메모리와 파일 읽기 시간은 여전히 영향을 준다.

### 폴더·하위 폴더 사진을 한 번에 등록

1. 참조 사진 방식에서 **사진별로 추가 ▾ → 폴더·하위 폴더 사진 모아서 추가** 또는 1번 사진 칸의 **폴더 사진 일괄 추가**를 연다.
2. **폴더 추가**로 폴더를 고르면 모든 하위 폴더의 이미지까지 모은다. 다른 폴더도 같은 버튼으로 이어서 추가한다. PC에서는 여러 폴더를 동시에 해당 영역에 끌어놓을 수도 있다. 선택창의 다중 폴더 선택 가능 여부는 브라우저·운영체제에 따라 다르다.
3. 모은 사진 수를 확인하고 **모은 사진 개별 대기열 추가**를 누른다. 각 사진을 사진 1로 하여 작업 하나씩 현재 설정으로 등록한다. 화면에 올린 참조 사진 1~9장과 별개이며 여러 사진을 한 영상의 참조로 합치는 기능은 아니다.

폴더 선택만으로는 등록하지 않는다. 선택한 묶음 안에서는 상대 경로·숫자 순으로 정렬하고, 이후 추가한 폴더는 뒤에 붙인다. 같은 상대 경로·파일 크기·수정 시각을 가진 항목은 중복 선택으로 취급한다. 실제 내용의 해시 비교는 하지 않는다. 이미지 외 파일은 제외한다. 폴더 선택은 `webkitdirectory`, 다중 폴더 끌어놓기는 [File and Directory Entries API](https://developer.mozilla.org/en-US/docs/Web/API/DataTransferItem/webkitGetAsEntry)를 사용하며 서버 PC의 임의 경로를 읽는 API는 추가하지 않는다.

모은 목록은 현재 브라우저 탭의 메모리에만 두고 새로고침하면 비운다. 선택 시에는 파일 핸들·메타데이터만 모으고 등록할 때 한 장씩 읽고 전송한다. 폴더 확인 중 **목록 비우기**를 누르면 늦게 도착한 확인 결과도 무시한다. 읽지 못한 폴더가 있으면 그 선택 묶음 전체를 추가하지 않고 이전 목록은 유지한다. 폴더별 사진 수 제한은 없다.

모델 목록 준비 전에도 사진을 모을 수 있다. 등록 버튼 아래에는 모델 연결·참조 방식·수정 모드 등 등록을 막는 조건을 표시하며, 실패하면 서버에서 받은 등록 안내도 해당 폴더 영역에 표시한다. MIME 형식이 비어 있거나 일반 파일로 전달된 사진은 JPEG/JFIF·PNG·WebP 등 확장자로 인식한다. 지원되지 않는 실제 이미지 형식이나 손상 파일은 서버의 이미지 검증에서 거절될 수 있다.

등록이 확인된 사진은 모은 목록에서 빼고 실패·미처리 사진은 남긴다. 추가 중단은 현재 요청 뒤에 적용하며 기존 작업은 유지한다. 응답을 확인하지 못한 사진은 중복 등록을 막기 위해 목록에서 빼고 작업 이력 확인을 안내한다. 이 항목을 자동으로 재시도하지 않는다. 대기항목 수정 중에는 등록을 막고 실행 중인 작업이나 기존 대기 순서를 변경하지 않는다.

일반 참조 모드에서는 사진 1을 전체 기준, 사진 2~9를 같은 인물의 얼굴 보조로 설명한다. 사진은 선택 순서대로 읽으며 인물 설명에 사진 번호가 이미 있어도 보조 역할을 포함한다. 직접 고친 최종 프롬프트에만 이 설명을 반영하려면 최종 프롬프트 아래의 `현재 사진 참조 문구만 반영`을 사용한다. 자세한 방법과 한계는 [얼굴 참조 안내](FACE_REFERENCES.md)에 정리했다.

**현재 프롬프트·설정 전체 대기에 적용**은 첫 대기항목을 불러오지 않고 버튼을 누른 순간의 현재 화면을 그대로 적용한다. 목록에 아직 불러오지 않은 대기항목도 포함하며 대상은 서버가 저장 시점에 다시 확인한다. 프롬프트·장면별 동작·유지 조건·카메라·모델·LoRA·스텝·샘플러·shift·화면비·해상도·길이·첫 장면 고정을 한 번에 적용한다. 사진·사진 관련 참조 방식·각 항목 시드·대기 순서는 유지하고 이미 시작한 작업은 건너뛴다. 일부에만 적용하려면 대기항목 체크박스와 **현재 설정 선택 항목에 적용**을 사용한다. 별도 항목 선택·수정 모드 진입·수정 저장 단계는 없다. 적용 후에도 현재 작성 내용과 사진은 그대로 남으며, 처리 중 사용자가 계속 편집한 내용도 덮어쓰지 않는다. 실패가 있으면 진행률 아래와 완료 안내에 고정된 사유별 건수를 표시한다. 인물 보호·실행 시작/대기열 제외·수정 충돌·반영 확인·ComfyUI 거절·기타 오류로 분류하며 프롬프트·파일명·작업 ID·임의의 예외 원문은 공유 진행 상태에 저장하지 않는다. 이전 버전에서 이미 끝난 처리의 사유는 복원하지 않는다.

`현재 작업 재시작`은 해당 작업의 설정을 유지한 재시작이다. 새 항목을 일반 대기열 끝에 추가하는 동작과 구분한다. 이력의 `불러오기`는 당시 저장한 화면 내용과 최종 프롬프트를 복원한다.

## 결과 확인

갤러리의 썸네일은 생성에 사용한 첫 번째 원본 사진이다. 갤러리만 열어 둬도 일반 생성·재생성의 완료 연결을 확인해 자동 갱신한다. 이력 삭제 전에는 이미 알려진 원본 연결을 별도로 보존한다. ‘원본 이미지 정보 없음’은 원본 연결 메타데이터가 없다는 뜻이며, 원본 파일의 삭제 여부를 판정한 문구는 아니다. 기존 작업 이력에 연결 정보가 남아 있으면 자동 갱신에서 반영할 수 있다. 이력과 연결 정보가 모두 사라진 항목은 사진을 추측해서 연결하지 않는다.

이미지 로딩이 일시적으로 실패하면 화면 근처의 항목만 최대 3회 재시도한다. 상단 ↻는 실패한 썸네일도 다시 시도한다. 로딩이 끝나면 ‘불러오는 중’ 문구를 숨기며, 빈 파일·잘린 썸네일 캐시는 서버에서 다시 만든다.

**얼굴인식강화**(사진 칸의 체크, 기본 꺼짐, 참조 방식에서만)를 켜면 사진이 2장 이상인 작업에서 사진 1은 원본, 나머지는 가장 큰 얼굴 주변을 여유 있게 자른 CPU 보조 크롭을 넣는다. 일반 대기열 추가와 사진 순차 추가 모두 적용되며(순차 추가는 작업마다 기준 사진이 바뀌므로 모든 사진의 크롭을 한 번씩 준비), 끄면 원본만 쓴다. 첫·끝 장면 방식의 사진은 실제 프레임이라 자르지 않고, 대기항목 수정은 원래 사진을 그대로 쓴다. 검출 실패·지나치게 작은 얼굴·안전한 크롭 범위가 없는 사진은 원본을 쓴다. 등록 후 크롭/원본 유지 장수를 안내한다. 사진 개별 추가는 작업당 사진 1장이라 해당 없다. 원본과 크롭은 기존 ComfyUI 입력 파일로 재사용하며 별도 인물 프로필을 만들지 않는다. 참조 중인 입력 파일을 임의로 지우면 대기 작업이나 재생성이 실패할 수 있다.

새 설치에는 `scripts/setup.ps1`이 CPU 검출을 준비한다. 기존 설치는 ComfyUI Python 환경에 `opencv-python>=5,<6`이 필요하며 `python scripts/install_face_detector.py --comfy <ComfyUI 폴더>`로 약 230KB 검출 모델을 설치한다. 모델은 SHA256으로 검증하며 사진 등록 중에는 외부 다운로드·사진 전송을 하지 않는다. 모델 라이선스는 [OpenCV Zoo MIT](https://github.com/opencv/opencv_zoo/blob/main/models/face_detection_yunet/LICENSE)다.

영상 체크박스는 최대 3개를 선택할 수 있다. 체크하지 않은 영상의 `재생`을 누르면 기존 선택을 해제하고 그 영상만 재생한다. 체크한 영상의 `재생`은 선택한 묶음을 재생한다. 창 너비는 영상 개수·영상 비율·기기 화면에 맞춘다.

LoRA 정보 표시는 전역 스위치로 켜고 끈다. 선택 재생창에서는 영상 바깥에 모든 LoRA와 강도를 표시하고 긴 이름은 화면 폭에 맞춰 줄인다. 이력 설정 팝업에서도 당시 설정을 확인할 수 있다. 설정 팝업은 이력 항목의 `설정` 버튼에 마우스를 올리거나 누를 때만 열린다(항목 전체에 마우스를 올려도 열리지 않는다).

목록 썸네일의 영상 데이터는 화면에 보이는 항목 중 최대 6개만 읽는다. 스크롤로 벗어나거나 다른 탭·재생창으로 이동하면 썸네일 버퍼를 해제한다. 모바일 터치에서 발생하는 가짜 마우스 오버로 썸네일을 재생하지 않는다.

## 갤러리

**작업 일시정지**는 현재 영상은 끝까지 완료하고 다음 작업부터 시작을 보류한다. 진행 중인 계산을 같은 지점에서 정지시키는 기능은 아니다. **작업 재개**를 누르면 기존 대기 순서대로 이어가며 사진·설정·시드·ID를 바꾸거나 대기열에서 제거하지 않는다. 일시정지 중에도 등록·수정은 가능하지만 생성은 재개할 때까지 시작하지 않는다. 제어는 메인 생성 화면과 갤러리 현재 작업 영역에 표시하며 기기 간 같은 상태를 공유한다. 상태는 ComfyUI 확장의 별도 불리언 파일로 보관한다.

기존 설치는 `python scripts/install_queue_pause.py`(ComfyUI 가 [위치 규칙](../README.md#설치와-실행) 밖에 있으면 `--comfy <ComfyUI 폴더>`)로 확장을 설치한 뒤 ComfyUI를 한 번 다시 시작해야 활성화된다. 설치 스크립트는 서버를 재시작하거나 대기열을 읽지 않는다. 활성화 전 버튼은 **일시정지 준비 필요**로 비활성화된다. UI 서버만 재시작하거나 브라우저를 새로고침하는 것으로 확장이 로드되지는 않는다. 실행 중인 작업을 유지하려면 확장 활성화를 위한 백엔드 재시작 시점을 별도로 정해야 한다.

최초 활성화 때 현재 작업을 완료하고 멈추려면 `python scripts/restart_backend.py --after-current --pause-after`를 사용한다. 비공개 로컬 백업을 먼저 검증한 뒤 대기 항목만 임시 분리하고, 실행 중인 작업에는 중단 요청을 보내지 않는다. 현재 작업이 끝난 뒤 비어 있는 백엔드를 재시작하고 정지 게이트 활성화를 확인한 후 기존 ID·순서·설정으로 대기 항목을 복원한다. 완료된 현재 작업은 다시 등록하지 않는다. 보호가 해제되면 새로고침한 화면에서 **작업 재개**로 이어갈 수 있다. 전환 중에는 기존 재시작 보호에 따라 등록·수정이 잠시 제한된다.

각 카드와 재생창의 **영상 정보 · ID**를 펼치면 갤러리 ID와 생성 작업 ID를 확인할 수 있다. **ID 복사**는 두 이름과 값을 함께 복사하고, 작업 이력이 없으면 갤러리 ID만 복사한다. 일반 HTTP 주소에서도 복사 대체 방식을 사용하며 실패하면 ID를 직접 선택해 복사할 수 있다. 갤러리 검색창에 어느 ID든 입력해 찾을 수 있다.

갤러리 썸네일은 생성에 사용한 첫 원본 사진이다. 축소 이미지는 캐시해 재사용한다. 원본 정보가 없는 항목에는 별도 안내를 표시한다. 갤러리 목록을 불러오는 것만으로 모든 영상 스트림을 읽지 않는다.

새 결과는 자동 갱신된다. 즐겨찾기와 휴지통 필터를 지원하며, 휴지통 항목은 복원할 수 있다. 영상 한 개를 열면 상단 메뉴를 가리고 창 크기에 맞춰 거의 전체 화면으로 재생한다. 영상 비율은 유지하며 자르거나 늘리지 않는다. 좌우 스와이프 또는 이전·다음 버튼으로 이동하고, 아래로 스와이프하면 추가정보를 펼치며, 위로 스와이프하면 재생창을 닫는다. 닫으면 이전 갤러리 스크롤 위치로 돌아간다.

추가정보·ID·재생성 버튼과 LoRA 정보는 영상 밖의 접이식 영역에 둔다. **정보·LoRA** 버튼으로도 펼치거나 접을 수 있고, LoRA 표시는 기존 전역 설정을 따른다. 영상 하단 재생 막대 조작, 여러 손가락 동작, 정보 영역 스크롤은 영상 이동·닫기 제스처에서 제외한다. 두세 영상을 함께 비교할 때는 기존 배치와 스크롤을 유지한다.

단일 영상 이동은 같은 플레이어를 재사용한다. 이미 목록에 있는 다음 영상을 재생할 때는 배경 갱신 완료를 기다리지 않아 Safari의 사용자 터치에 연결된 재생 동작을 유지한다. 기기에서 재생이 차단되면 영상의 기본 재생 버튼을 누른다.

## 설정을 가져와 재생성

1. 다시 만들 대상 영상의 `재생성`을 누른다.
2. 설정을 가져올 다른 영상의 `이 영상 설정 가져오기`를 누른다.
3. 대상·설정 출처를 확인하고 `우선 재생성`한다.

출처의 프롬프트·모델·LoRA·스텝·샘플러·스케줄러·shift를 복사한다. 대상의 원본 사진·시드·길이·화면비·해상도·첫 장면 고정·모드는 유지한다. 기존 영상은 그대로 남기고 새 결과를 만든다. 이력이 없거나 모드·참조 사진 조건이 맞지 않으면 제출하지 않는다.

실행 중인 작업은 중단하지 않는다. 재생성을 연달아 제출하고 모두 아직 대기 중이라면 나중 요청이 먼저 실행된다. 이미 시작한 재생성의 순서는 바뀌지 않는다. 같은 요청의 응답을 다시 확인하는 경우 중복 제출을 막는다.

재생성 완료 항목에는 완료 표시를 붙인다. 재생창이 닫힌 뒤 갤러리 상단으로 한 번 이동해 새 결과를 보여준다. 갤러리 상단에는 현재 실행 작업의 진행률과 대기 개수를 표시한다.

## 작업별 실제 생성 시간

작업 이력은 **시작 시각 – 소요 시간**을 ‘11/19 02:33 – 05:00’처럼 한 줄에 굵게 표시한다. 소요 시간은 분:초이며 1시간 이상도 ‘61:01’처럼 전체 분으로 표시한다. 완료 시각과 별도 초 단위 줄은 표시하지 않는다. 갤러리의 각 영상 카드에는 날짜 아래 별도 줄에 ‘생성 05:00’처럼 생성 소요 시간을 분:초로 표시한다. 기록이 없는 이전 영상에는 ‘생성 시간 기록 없음’을 표시한다. 제목·모델·스텝·LoRA·첫 장면 고정·크기·영상 길이·시드 등은 기본으로 접힌 **확장 정보** 안에 둔다. PC에서는 확장 정보에 마우스를 올려 팝업으로 확인하고 모바일·키보드에서는 눌러 펼친다. 목록이 갱신돼도 펼친 항목은 유지한다. ComfyUI의 execution_start와 execution_success(실패/중단 시 해당 종료 이벤트) 밀리초 시각으로 계산하므로 대기열에 머문 시간은 제외하고 모델 로딩·계산·저장 시간은 포함한다. 영상 길이(예: 5초)와 별도 정보다.

갤러리 상단은 `현재 작업 · 42% · 경과 05:00`처럼 현재 한 작업의 경과 시간을 분:초로 표시한다. 서버 조회는 기존 간격을 유지하고 화면의 단조 시계로 초마다 갱신한다. 실행 시작 이벤트의 시각을 저장해 브라우저 새로고침과 UI 서버 재시작 뒤에도 이어서 표시하며, 다음 작업은 새로 카운팅한다. 시작 기록이 없는 기존 실행 항목은 서버가 처음 확인한 시점부터 측정하고 `확인 후 05:00`으로 구분한다. 숨긴 탭에서는 카운터를 쉬고 완료·연결 실패 시 멈춘다.

시작·완료 시각과 generation_seconds를 이력에 저장하고 소요 시간은 갤러리 연결 메타데이터에도 남겨 이력을 지워도 유지한다. UI 서버만 다시 시작해도 ComfyUI의 실행 기록에서 시간을 얻을 수 있다. 이전 기록에 타임스탬프가 없으면 등록일·파일 수정일로 소요 시간이나 완료 시각을 추정하지 않는다. 이력에는 ‘소요 시간 기록 없음’을 표시한다. 시작 시각이 없는 이전 항목은 등록 시각을 표시하며 툴팁으로 구분한다.

## 폴더별 여러 사진을 번갈아 사진 1로 등록

‘사진별로 추가’ → ‘폴더·하위 폴더 사진 모아서 추가’에서 폴더를 모은 뒤 **폴더별 번갈아 사진 1로 추가**를 누른다. 50장이면 총 50개 작업이 등록된다. 같은 폴더의 자연스러운 파일명 순서로 1번은 1~9번, 2번은 2~10번을 쓰고 마지막은 50번+1~8번처럼 순환한다. 폴더에 9장 미만이면 있는 사진을 중복 없이 모두 사용한다. 여러 폴더를 모아도 하위 폴더 경로별로 나눠 섞지 않는다.

현재 모델·LoRA·길이·화면·첫 장면 고정·얼굴 보조 참조 설정을 한 번 복사해 전체 등록에 사용한다. 시드가 있으면 등록 위치에 따라 1씩 증가하고 비어 있으면 작업별 무작위다. 얼굴 보조 참조가 켜졌으면 사진 1은 원본을 쓰고 나머지 참조는 기존 CPU 얼굴 크롭을 재사용한다. 원래 편집 화면의 사진과 설정은 바꾸지 않는다.

사진은 폴더마다 한 장씩 준비해 한 번 업로드하고, 각 작업은 준비된 참조 ID만 보낸다. 한 작업의 모델 참조 제한은 계속 9장이다. ‘추가 중단’은 현재 요청 이후 등록만 멈추며 이미 대기열에 들어간 영상은 유지한다. 같은 선택 목록에서는 확인된 사진 1을 다시 등록하지 않아 남은 항목을 이어갈 수 있다. 응답 미확인 항목은 중복 방지를 위해 재전송하지 않으며 이력에서 확인한다. 모두 새 설정으로 다시 등록하려면 목록을 비우고 폴더를 다시 선택한다. 새로고침하면 브라우저의 파일 선택은 다시 필요하다.

## 일괄 수정 진행률

전체·선택 대기항목 수정 저장과 Grok의 일괄 적용 중에는 화면 상단에 진행률 바와 `처리 120/600 · 성공 118 · 실패 2 · 05:00`을 표시한다. 실제 항목별 반영 결과로 집계하며 시작된 작업을 수정하지 못한 경우 등 미적용 건도 실패에 포함한다. 진행률은 처리 건수/대상 건수이며 예상 시간으로 올리지 않는다. 작업 문구·사진·결과 경로는 진행률 API에 포함하지 않는다.

상태는 서버가 보관해 다른 기기와 새로고침 뒤에도 확인할 수 있다. 연결이 끊기면 결과 확인 중으로 표시하고 작업을 자동 재전송하지 않는다. 일괄 수정이 진행 중이면 UI 서버 재시작 준비를 거절하며, 정상 완료·중단 후 다시 시작할 수 있다. 수정 처리는 기존 순차 방식이며 이 기능은 대량 반영 자체의 속도 최적화는 아니다.


## 대기열 전체 적용 속도와 실패 처리

현재 입력 기준 전체 적용과 Grok의 대기열 일괄 수정은 최대 25개씩 처리한다. 적용 한 번 동안 템플릿과 모델·LoRA 목록/판정 정보를 재사용하며, 전체 대기열 조회·반영 대조·작업이력 전체 저장은 묶음마다 수행한다. 실행 직전 상태는 작은 ComfyUI 작업 상태 API로 확인하고, 해당 API가 없는 이전 버전에서는 기존 조회로 안전하게 돌아간다. 진행률은 반영 확인과 이력 저장이 끝난 항목 수를 세므로 작은 묶음 단위로 증가할 수 있다.

사진·시드·생성 방식·대기번호·기타 ComfyUI 작업 메타데이터를 보존하며, 실행이 시작되거나 다른 수정이 감지된 항목은 제외한다. 응답이 끊겼을 때 자동 재등록하지 않고 먼저 실제 반영 여부를 확인한다. 성공 응답만으로 완료를 표시하지 않으며, 확인되지 않은 항목은 미적용으로 분리한다. `queue-edit-recovery/` 사본은 네이티브 반영 대조와 이력 저장이 모두 끝난 뒤 제거한다. 중간 종료 뒤 UI 서버가 다시 켜지면 실제 반영과 일치하는 이력만 복구하고 작업을 새로 제출하지 않는다. 이 사본은 개인 데이터이므로 Git에 포함하지 않는다.

600개 합성 대기열 검사에서 전체 대기열 조회 49회, 이력 전체 저장 24회, 모델/LoRA 목록 조회 각 1회를 확인했다. 이는 정상 처리 경로의 호출 수이며, 실제 영상 생성 중 전체 적용 소요시간을 측정한 수치는 아니다. 이전 ComfyUI 버전이나 오류 복구 경로에서는 조회가 늘 수 있다.


## 휴대폰 세로 화면과 사진 비율

4번 출력·확인의 **휴대폰 세로로 맞추기 · 9:16 / 720p**를 누르면 현재 화면비와 화질만 바뀐다. 사진·프롬프트·모델·LoRA·시드·길이와 기존 대기열은 그대로 유지하며 바로 생성하거나 일괄 수정하지 않는다. 생성 크기는 모델의 32배수 규격에 맞춰 **736×1280**이므로 표준 9:16과 약간 다르다.

첫/끝 프레임 방식(I2VA/FL2VA)은 DaSiWa의 기존 `Fill and crop` 입력 스케일링을 사용해 원본 비율대로 화면을 채운 뒤 중앙에서 잘라낸다. 사진을 가로나 세로로 강제로 눌러 맞추거나 패딩을 넣지 않는다. 참조 방식(REF2VA)의 보조 참조사진은 `Auto`로 원래 비율을 유지하고, 첫 장면 고정은 기존 네이티브 AddGuide의 비율 유지 중앙 크롭을 그대로 사용한다. 원본 업로드 파일과 썸네일 연결은 바꾸지 않는다. 크롭 때문에 가장자리의 인물·사물이 잘릴 수 있으므로 중앙에 주요 피사체가 있는 사진이 유리하다. 이 처리는 입력 이미지의 기하학적 늘어남을 막는 기능이며 생성 모델의 인물 표현 변화까지 보장하지는 않는다.

일반 사진 등록도 EXIF 회전을 반영한 표시 크기로 화면을 계산한다. EXIF 방향 표시가 있는 사진(휴대폰으로 세워 찍은 사진 등)은 화소를 세운 사본(JPEG 는 품질 95·4:4:4, 그 밖은 PNG)으로 올리고, 방향 표시가 없는 사진은 받은 바이트 그대로 올린다(모델에 사진을 넘기는 노드가 EXIF 방향을 무시하기 때문). 새 감지 모델은 추가하지 않는다. 이후 새로 등록하거나 명시적으로 수정하는 작업부터 적용되며 실행 중인 작업은 바꾸지 않는다.


### 인물 보호와 원본 비율 자동 유지

사용자 우선순위는 인물 보존이다. **인물 잘림 방지**가 기본으로 켜져 있고 휴대폰 버튼도 이를 켠다. 인물 검출 영역 전체에 여유를 더해 기존 중앙 크롭 안에 들어오는 경우에만 요청 화면비를 쓴다. 여러 사람이 있으면 검출된 사람 전체를 포함한다. 팔을 벌린 자세·화면 가장자리의 인물처럼 잘릴 우려가 있거나, 검출이 불확실/실패/미설치이면 그 사진만 **원본 화면비(auto)** 로 생성한다. 32픽셀 배수 반올림이 보호 영역을 자르면 가까운 크기 외에 원본 비율이 정확히 일치하는 크기도 찾는다. 이때 픽셀 예산을 늘리지 않으므로 실제 크기는 낮아질 수 있다. 안전한 크기가 없으면 해당 항목은 기존 상태로 유지하고 실패 사유를 표시한다. 크롭 위치를 임의로 옮기거나 사진 자체를 잘라 업로드하지 않으므로 원본·얼굴 보조 참조·썸네일은 보존된다. 기존 대기/실행 항목은 자동 변경하지 않는다.

첫/끝 프레임 모드는 두 사진 모두 검사하고, 사진 순차 추가는 각 사진이 1번이 될 때 개별로 판단한다. 반복 생성/대기 수정은 저장된 숫자 영역을 재사용한다. 크롭 판정에서는 기존 검출 여유에 움직임용 여유를 추가한다(좌우 각각 원본 폭의 최소 2.5%, 상하 각각 높이의 최소 1.5%; 인물 영역이 크면 비례해 늘림). 저장된 영역을 재사용할 때도 적용하되 누적해서 키우지는 않는다. 원본 사진 경계 밖의 공간을 새로 만들지는 않으며, 생성 중 큰 동작까지 잘리지 않는다고 보장하지는 않는다. 실제 크기와 원본 비율 유지 여부는 항목별로 저장하며, 등록 안내에 원본 비율 유지 건수를 표시한다. 인물 보호를 끄면 이전의 중앙 크롭을 사용할 수 있다. 화면비 auto는 원래 비율을 우선하되 최종 픽셀 크기는 모델의 배수 규격으로 반올림된다.

검출기는 OpenCV Zoo YOLOX-S(약 35.9MB)를 **CPU 한 스레드**로 사용하며 CUDA·영상 생성 모델을 사용하지 않는다. 설치/검증은 `python scripts/install_person_detector.py`로 한다(`setup.ps1` 이 함께 설치하며, ComfyUI 가 위치 규칙 밖에 있으면 `--comfy <ComfyUI 폴더>`). 검출기가 없으면 인물 보호 없이 원본 비율로 등록된다. 검출기는 영상 생성 프레임을 분석하는 것이 아닌 등록 사진의 구도를 판단하는 보조 장치다. 검출에는 오차가 있을 수 있고 영상 모델이 생성 과정에서 움직임이나 구도를 바꾸는 것까지 보장하지 않는다. 원본 사진이나 영상은 외부로 보내지 않는다.


모델 규격의 픽셀 반올림으로 원본 비율에서도 검출된 인물 경계가 잘릴 경우, 픽셀 예산을 늘리지 않는 가까운 크기에서 다시 검사한다. 서로 다른 첫/끝 프레임처럼 인물 전체를 보존할 수 있는 크기를 찾지 못하면 잘린 결과를 자동 등록하지 않고 사진 비율을 맞추도록 안내한다. 감지가 불확실한 경우 원본 비율을 우선하며 모델 규격에 따른 소폭의 비율 오차는 있을 수 있다.
