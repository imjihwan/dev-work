# Grok CLI 프롬프트 도우미

공식 `@xai-official/grok` **1.0.89**를 별도 폴더에 설치하고, **계정 로그인**으로 Grok 4.7을 호출한다. API 키·브라우저 자동 조작·비공식 프록시를 쓰지 않는다. API 충전과 CLI 구독 사용량은 구분해야 하며, 실제 이용 권한과 한도는 로그인한 계정에 따른다.

## 설치와 로그인

```powershell
.\ComfyUI\.venv\Scripts\python.exe -X utf8 scripts\install_grok_cli.py
.\Connect-Grok.ps1
```

다른 ComfyUI 위치는 설치 스크립트의 `--comfy`, 로그인 스크립트의 `-ComfyDir`로 지정한다. 로그인은 표시된 기기 인증 URL에서 직접 승인한다. API 키나 토큰을 채팅·Git에 붙이지 않는다. 새 PC에서는 다시 설치·로그인해야 한다.

CLI는 `local-prompt-helper/grok-cli/bin/grok.exe`, 전용 계정 설정은 `local-prompt-helper/grok-account`에 둔다. 사용자의 다른 Grok 설치·계정 설정을 변경하지 않는다. 모델 가중치를 설치하지 않으며 로컬 CPU 도우미의 RAM 시작 조건도 적용하지 않는다.

별도의 [영상 제작 도우미](PRODUCTION_ASSISTANT.md)는 오른쪽 아래 패널에서 현재 입력·최종 문구·다른 대기 항목·웹 기능을 다룬다. 아래 내용은 기존 2번의 프롬프트 도우미 안내다.

## 일반 탭에서 대화하기

1. 프롬프트 도우미에서 **Grok CLI · 계정 로그인**을 선택한다.
2. 질문을 입력하고 **상의하기 · 내용 변경 없음**을 누르면 설명·실행 가능성·개선 제안을 받는다.
3. **수정안 만들기**는 초안 또는 요청한 부분의 변경안을 만든다. 최근 대화와 아직 적용하지 않은 최신 수정안을 참고한다.
4. 미리보기를 확인하고 **내용 칸에 적용**을 눌러야 입력 내용이 변경된다. 여러 차례 보완한 최신 수정안 전체를 적용한다.

최근 대화 최대 12개 메시지를 화면 메모리에서 참고한다. 입력 원문이나 고정 설정이 바뀌면 이전 대화·미적용 제안은 무효화한다. **새 대화**는 화면의 대화 맥락을 초기화하며 입력 원문은 유지한다. Grok 서비스나 CLI가 보관한 기록을 삭제하는 기능은 아니다. 이어 만들기 탭에서도 Grok으로 편별 초안·부분 수정·검토를 사용할 수 있다.

## 고정 조건과 자연어 동작

누가/무엇, 사진에서 그대로 유지할 것, 장소·분위기·카메라는 기존 코드가 소유한다. Grok은 요약·장면 동작·소리·음악만 제안하고, 원테이크·참조 수·길이·첫 장면 고정 상태를 조건으로 전달받는다. 부분 수정은 기존의 정확한 문자열 교체 검증을 사용한다. 새 카메라·컷·없는 사진 참조를 검사하고, 새 초안에서 위반하면 한 번만 교정 후 재검사한다. 기존 저장 프롬프트나 대기열을 자동 마이그레이션하지 않는다.

일반 탭의 **동작 입력 방식 → 한 칸으로 작성 · 시간 지정 없이**는 큰 텍스트 칸 하나를 사용한다. 초 단위로 적을 필요가 없다. 워크플로에는 시작 시각 0인 한 구간으로 전달되며 템플릿·노드 구조를 변경하지 않는다. 시간별 동작을 한 칸으로 바꾼 뒤 편집하지 않고 되돌리면 기존 시각을 복원한다. 편집한 뒤 되돌리면 최신 문구가 0초 구간으로 남고 예전 동작을 되살리지 않는다. 선택은 저장 설정·화면 동기화·새 이력·내용 일괄수정·설정 복사 재생성에 함께 전달된다.

## 전송 범위와 실행 제한

- 외부 전송: 사용자가 도우미에 입력한 요청, 고정 조건, 선택한 현재 프롬프트/미적용 초안, 최근 대화. 이어 만들기는 사용자가 편집 중인 네 편 시나리오와 연결 상태도 참고한다.
- 전송 제외: 사진 바이트·파일 경로·영상·작업이력·ComfyUI 대기열. 요청 검증이 허용한 텍스트 필드만 CLI로 넘긴다.
- 전용 빈 임시 작업 폴더에서 매번 새 세션을 사용한다. `agentsMd`, 스킬 탐색, 기본 도구 주입을 끄며, 전용 프로필에는 `todo_write` 하나를 선언한 다음 명시적으로 제거한다. 이 버전은 처음부터 빈 도구 구성을 거절하고, 존재하지 않는 `--tools` 값은 제한을 무시하므로 그 방법을 사용하지 않는다.
- `dontAsk`, 전체 거절 규칙, 하위 에이전트·웹·메모리 비활성화도 적용한다. 결과 이벤트의 도구·스킬·MCP 목록이 모두 비고 인증 방식이 `oauth`일 때만 응답을 받는다. API 키·공급자 환경 설정을 상속하지 않으며 API로 자동 전환하지 않는다.
- 문구는 명령줄 인수 대신 임시 파일로 전달하고 완료·오류·취소 후 삭제한다. CLI 원문 오류·생각 과정·토큰·계정 식별자를 UI 상태나 서버 로그에 내보내지 않는다. 한 번에 도우미 한 작업이며 CLI 호출 제한은 빠르게(low) 180초, 균형(medium) 300초, 정밀(high) 600초, 최대(xhigh) 900초다. 제작 도우미의 조회 전체와 프롬프트 도우미의 작성·검토 전체에는 900초 예산을 적용하며 각 호출에는 남은 예산을 적용한다. 취소하면 해당 CLI 프로세스를 종료하지만 이미 처리된 요청은 계정 사용량에 포함될 수 있다.

**CLI 자체의 세션·진단 기록은 전용 계정 폴더에 남을 수 있으며 Git에서 제외한다.** 외부 보관·학습 정책은 API 정책을 그대로 가정하지 않고 Grok CLI `/privacy` 및 계정 설정을 확인한다. 화면의 새 대화는 외부 기록 삭제나 보관 해제를 의미하지 않는다.

## 검증

개인 작업·사진·결과물을 조회하지 않고, 합성 블록 동작으로 계정 로그인, 도구 없는 호출, 단일 구간 초안+검토, 설명만 받기, 음악만 정확히 수정하기를 실제 실행했다. 모의 테스트는 인증 누락·API 인증 거절·도구 노출 거절·취소·요청 필드 제한·최근 미적용 초안 이어 수정·원문 변경 시 대화 초기화와 단일 입력의 저장·시간 복원을 검사한다. 실제 영상 생성은 하지 않았다.

공식 참고: [CLI](https://docs.x.ai/build/cli/headless-scripting), [권한](https://docs.x.ai/build/features/permissions), [개인정보](https://docs.x.ai/developers/faq/security), [공식 소스](https://github.com/xai-org/grok-build).

## 응답 방식과 전달량

Grok 4.7에 추론 강도를 명시한다. 기존 프롬프트 도우미는 `high`를 유지하며, 제작 도우미는 **정밀(high)** 기본값과 **최대(xhigh)·균형(medium)·빠르게(low)**를 제공한다. 같은 모델의 추론 강도 선택이며 다른 모델로 전환하거나 유료 API로 우회하지 않는다. 선택은 접속 주소별 브라우저에 기억한다.

JSON 직렬화의 구분 공백만 줄이고 문자열 내부의 공백·줄바꿈·고정 조건은 보존한다. 제작 도우미의 대기열 목록은 처음 20개 상태 메타데이터만 전달하고 추가 페이지나 지정 항목을 필요할 때 조회한다. 전체 원본 스냅샷과 변경 감지 검증은 로컬에 유지한다.

2026-11-19 계정 CLI의 `grok models` 결과에는 `grok-4.7` 한 모델이 표시되었다. 현재 연결도 이미 이 모델을 사용한다. 웹 앱의 모델 선택지와 CLI 계정의 선택지는 같다고 가정하지 않는다. [공식 추론 강도 문서](https://docs.x.ai/developers/model-capabilities/text/reasoning), [CLI 명령](https://docs.x.ai/build/cli/reference).

## 타임아웃 진단

추론 강도와 관계없이 180초에 종료하던 고정 제한을 제거했다. 취소는 계속 즉시 처리하고 앱에서 자동 재요청하지 않는다. 진행 상태에는 현재 호출의 대기 시간과 제한 시간을 숫자로 제공한다.

`local-prompt-helper/grok-timings.jsonl`에 UTC 시각, 모델, 추론 강도, 입력 바이트 수, 경과 시간, 제한, 종료 분류와 가능한 CLI 보고 시간·토큰 개수만 남긴다. 요청·답변 원문, 생각 과정, 인증 토큰, 계정 식별자, 작업/세션 ID를 기록하지 않는다. 128KiB를 넘으면 이전 파일 하나로 교체해 용량을 제한하고 진단 기록 실패로 정상 답변을 실패 처리하지 않는다. 이 폴더는 Git에서 제외한다. 제한 조정은 응답을 더 기다리도록 하는 변경으로, Grok 서버의 지연 자체를 없애지는 않는다.
