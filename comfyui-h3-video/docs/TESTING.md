# 개인 데이터 없이 검증하기

테스트는 저장소 `simple_ui/`를 읽는다. ComfyUI 실행, 모델 다운로드, 실제 작업 이력이나 미디어 열람이 필요하지 않다. API 테스트는 가짜 서버 응답과 임시 파일을 사용하고 UI 테스트는 Node.js의 가짜 DOM/플레이어를 사용한다.

Python 3.12 이상과 Node.js를 준비한다.

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-test.txt
.\.venv\Scripts\python.exe -m unittest discover -s scripts -p "test_*.py"
Get-ChildItem scripts\test_*.cjs | ForEach-Object { node $_.FullName; if ($LASTEXITCODE -ne 0) { throw 'UI test failed' } }
```

Python 패키지가 이미 준비된 설치본에서는 `ComfyUI/.venv/Scripts/python.exe`를 사용해도 된다. 테스트 대상 소스는 여전히 저장소 `simple_ui/`다. 일부 Python 테스트는 `GALLERY_TEST_SOURCE` 또는 `REFERENCE_TEST_SOURCE`, Node UI 테스트는 첫 번째 파일 경로 인자로 격리된 스테이징 소스를 지정할 수 있다.

FFmpeg가 PATH에 있으면 네 편 병합 테스트가 임시 폴더에 단색 영상과 무음 오디오를 생성해 길이·화면 크기·오디오 트랙을 검사한다. 없으면 해당 테스트만 건너뛴다. 이 합성 테스트는 실제 생성 모델을 사용하지 않는다.

고정된 DaSiWa 커스텀 노드가 설치되어 있으면 네이티브 그래프 검증기와의 통합 검사 2개도 실행한다. 소스만 있는 환경에서는 이 2개만 건너뛰며 나머지 가짜 백엔드 검사는 그대로 실행한다.

- 1/5/15초 새 초안의 장면 시작 문법 범위, 부사가 포함된 중복 카메라 지시 감지·최대 한 번 새 초안 재작성·계속 위반 시 적용 거절과 고정 칸 보존.
- 로컬 번역의 정밀 기본값·방식별 캐시·CPU 전용 실행·RAM 제한·도우미 우선 처리, 긴 입력 무손실 분할·선택 번역·원문 보존·참고 표기 검증·지연 응답 무시.
- 네 단계 생성의 사용자 확정, 후속 단계 재검토, 실패/재시작 중복 제출 방지, 합성 영상 병합.

2026-11-17 실제 CPU 검증: 32GiB 환경에서 영상 생성 프로세스를 유지한 채 별도 합성 텍스트만 `/api/prompt-helper/start`로 보냈다. DutchIT 8B Q4_K_M, CPU 두 스레드, 8,192 문맥, Q8 키·값 캐시, 재배열 끄기에서 새 초안·검토가 155.5초, 음악만 부분 수정·검토가 103.4초에 완료됐다. 최대 도우미 작업 집합은 5.07GiB, 두 성공 요청의 최소 여유 RAM은 4.14GiB였다. 고정 칸이 응답 수정 대상에 없고, 새 동작 칸에 카메라 문구가 중복되지 않으며, 부분 수정은 음악만 바꾸고 나머지 문장·시각을 포함하지 않음을 확인했다. 실제 사진·이력·영상이나 해당 경로는 조회하지 않았다. 여유가 부족하면 이 측정 때문에 시작 제한을 낮추지 말고 요청을 보류한다.

이 측정은 기능·자원 제한 확인이다. 모델의 검토가 `ok`여도 모든 의미 조건의 충족이나 영상 생성 속도 영향 0을 입증하지 않으며, 생성된 초안은 적용 전에 확인해야 한다.

## 제작 도우미 채팅 UI

## Grok 응답 개선 검증

CLI 테스트는 명시적 추론 강도, 모델·실행 제한 보존, JSON 구분 공백 축소와 문자열 내부 공백 보존을 검사한다. 앱 테스트는 1,000개 가짜 대기열의 최초 20개 전달, 전체 로컬 검증 보존, 뒤쪽 항목 접근, 페이지 경계, 요청 내부 중복 조회 재사용과 요청 간 캐시 분리를 검사한다. 가짜 DOM은 기본 정밀 모드·최대 모드 선택 보존·요청 전달·처리 단계·0.6초 폴링을 검사한다. 실제 CLI 호출도 합성 폼과 가짜 대기열만 사용한다. 실제 작업 문구·사진·결과물을 열거나 대기열을 제어하지 않는다.

## 공통 대화 검증

`test_production_chat.py`는 임시 파일로 최초 이관, 개인정보·실행 대상 제외, 동시 revision 충돌, 브라우저 없이 완료된 답변 보관, 중단 복구, 원자적 저장 실패, 새 대화 이후 이전 변경안 거절과 실행 결과 공유를 검사한다. 기존 UI 테스트는 서로 다른 가짜 기기·저장소로 공통 기록, 후속 맥락, 기기별 초안, 읽기 전용 제안, 다른 기기의 새 요청과 충돌 보호를 검사한다. 실제 공통 대화 엔드포인트의 내용은 점검하지 않는다.

가짜 DOM으로 접힌 대화의 새 답변 점, 확인 후 해제, 실제 읽고 있는 대화의 자동 확인, 숨긴 화면의 미확인 유지, 공유 메시지의 새 도착, 새로고침 뒤 읽음 유지와 원문 없는 읽음 마커를 검사한다.

Grok 타임아웃 회귀 검증은 가짜 시계로 이전 180초를 넘긴 정상 응답 수신, 모드별 종료·하위 요청의 남은 예산 적용, 자동 재요청 없음, 숫자 진행 상태·원문 없는 진단, 진단 디스크 실패 시 정상 응답 보존과 전체 900초 예산을 검사한다. 실제 기다리는 긴 테스트나 사용자 요청 재실행은 하지 않는다.

요청 중 새로고침은 가짜 서버의 기존 active ID로 복원해 단계·차수·시간 표시, 새 요청/실행 재전송 없음, 정확한 도우미 ID 취소와 완료 후 대기 문구·잠금 해제를 검증한다.

## 실시간 CLI 진행 검증

가짜 NDJSON과 실제 Python 자식 프로세스가 합성 이벤트를 시간차로 내보내도록 해 종료 전 연결·추론·답변·검증 단계 수신, 내부 추론/미완성 JSON 유출 방지, 조용한 스트림의 취소, 크기 제한, 잘못된 인증/도구 구성 거절, 모드별/전체 시간 제한을 검증한다. 가짜 공유 대화는 신호 수신 중 디스크/메시지 revision 불변, 같은 revision의 진행 갱신, 새 호출의 초기화, 완료·이전 요청 무시를 검사한다. 가상 DOM으로 다른 기기·새로고침 화면의 추론/답변 단계와 마지막 수신 시간, 원문 미표시와 완료 잠금 해제를 검사한다. 실제 작업·사진·결과물은 조회하지 않는다.

## 대화형 변경 검증

가짜 폼의 공통 항목 네 종류에서 항목명 없는 후속 승인과 미적용 수정안 전달이 가능함을 검사한다. 숫자 범위·원문/입력 변경·중복 실행·조언의 자동 실행 제외는 그대로 검증한다. 단독 ‘응’은 자동 실행 대상이 아니며 대화 맥락과 실행 의도가 있을 때만 후보로 인정한다. 공유 대화 테스트는 승인 직전 수정안 상태를 모델에 전달하고 이전 계획의 실행 권한을 무효화한 채 새 계획을 생성하는지 확인한다. 폐기된 앱 오류는 모델 맥락에서만 빠지고 저장된 표시 기록에는 남는지 검사한다. 실제 CLI 검증은 가짜 카메라 문구와 블록 대상만 사용하고 실제 앱 작업을 조회/변경하지 않는다.
