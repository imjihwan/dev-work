# 로컬 프롬프트 작성 도우미

## DutchIT H3 통합 (2026-11-17)

일반 화면과 네 편 이어 만들기의 **CPU 프롬프트 도우미**에서 **DutchIT H3 · 상세 작성 (8B)** 또는 **기존 도우미 · 가볍게 (2B)**를 선택한다. 첫 기본 선택은 DutchIT이며 선택만 이 브라우저에 저장한다. 기존 API 요청이 엔진을 생략하면 2B를 사용해 이전 클라이언트와 호환한다. RAM 부족이나 오류 때 엔진을 몰래 바꾸지 않는다.

[DutchIT/minimax-prompt-enhancer](https://huggingface.co/DutchIT/minimax-prompt-enhancer)는 별도 학습 가중치가 아닌 MiniMax용 지시문 모음이다. `Modelfile.ref`의 동작·소리·시간 연계 원칙을 기존 편집기에 맞게 수정했으며, 기반인 Huihui Qwen3-VL 8B Instruct abliterated의 Q4_K_M 가중치를 기존 CPU llama.cpp에서 실행한다. 원본 지시문·라이선스·고정 리비전과 수정 사항은 `third_party/dutchit/`에 보관한다. 원본 Modelfile 전체를 그대로 실행하거나 Ollama를 추가 설치하지 않는다.

**기존 설정 마이그레이션은 필요 없다.** 입력·저장 설정·이력·대기열·워크플로 구조를 바꾸지 않는다. 인물 정의, 유지 조건, 장소·분위기·카메라의 세 칸은 그대로 참고만 하고 수정하지 않는다. 기존 카메라의 연속적인 줌/이동 후 고정, 원테이크, 첫 장면 고정과 사진 수를 전달한다. 원본의 자동 컷·기본 길이·사진별 역할 추정은 사용하지 않는다. 새 동작 문구에서 컷 전환(원테이크일 때), 촬영 지시 또는 등록하지 않은 사진 참조를 발견하면 적용하지 않고 재작성을 안내한다. 기존 문장을 일괄 정리하거나 다시 저장하지 않는다. 이 검사는 생성 모델이 실제 영상에서 지시를 완벽히 따름을 보장하지 않는다.

**텍스트 전용이다.** 사진을 모델에 보내지 않으며 얼굴 인식·이미지 분석 기능이 추가되는 것은 아니다. 사진 1은 주 참조, 나머지는 같은 인물의 보조 참조라는 현재 앱 규칙을 따른다. 설명 분량보다 실제 가능한 동작·접촉·이동·마무리를 구체화하며, 짧은 동작을 억지로 늘리지 않는다. 현재 문장 편집·검토·적용 전 확인은 그대로 제공한다.

DutchIT 모델은 약 5.03GB(4.68GiB)다. CPU 두 스레드, GPU 레이어 0, 낮은 우선순위로 요청할 때만 실행한다. 시작 전 RAM 여유 **8GiB**, 실행 중 최소 **2.5GiB**를 확인하며 작성·검토 전체 제한은 900초(준비 대기 최대 60초 별도)다. 번역 프로세스는 도우미 실행 전에 쉬게 하지만 영상 작업은 중지하지 않는다. CPU·RAM·디스크를 공유하므로 영상 생성에 영향이 전혀 없다고 보장할 수는 없다. 실제 채팅 템플릿의 토큰 수를 확인해 출력 여유를 포함한 8,192 토큰을 넘으면 원문을 자르지 않고 요청을 거절한다.

설치 시 `--engine dutchit`은 DutchIT만, `--engine legacy`는 기존 모델만, 생략 또는 `--engine all`은 둘 다 준비한다. 가중치와 런타임의 크기·SHA256을 검증하고 모델은 Git에 넣지 않는다.

```powershell
.\ComfyUI\.venv\Scripts\python.exe scripts/install_prompt_helper.py --engine dutchit
```

## 공통 사용 방식

**다국어 요청 보호**: 아래 지어내기 방지의 자동 삭제는 영어 단어 대조가 가능한 요청에 적용한다. 요청·고정 조건·기존 내용에 한국어 등 비ASCII 문자가 있으면, 생성된 영어 단어가 같은 의미의 번역인지 코드만으로 판단할 수 없으므로 문장을 유지한다. 검토 결과에는 요청 누락을 단정하지 않고 언어 간 대응 확인이 필요하다고 안내한다. 부분 수정도 같은 방식으로 안내하며 원문을 보존한다.

화면의 **2. 내용 → 프롬프트 작성 도우미 · 로컬 CPU**에 원하는 영상이나 수정 요청을 적고 **프롬프트 작성**을 누른다. 결과를 확인한 뒤 **내용 칸에 적용**한다. 현재 내용도 다듬으려면 **현재 내용 칸도 함께 참고**를 선택한다.

참고를 체크하면 전체 초안을 재작성하지 않고 요청한 변경분만 제안한다. 변경 전·후 문구를 확인하고 적용하며, 수정하지 않은 문장·공백·장면 순서·시각은 보존한다. 직접 편집한 최종 프롬프트가 있으면 그 원문을 대상으로 수정한다. 수정 위치가 중복되거나 원문을 정확히 찾지 못하면 적용하지 않는다. 작성 중 원문을 바꿨을 때도 다시 작성해야 한다.

도우미는 텍스트만 받는다. 사진·작업 이력·대기열을 읽거나 바꾸지 않으며, 사진·모델·시드·길이 설정도 변경하지 않는다. 결과는 적용 전까지 기존 내용에 영향을 주지 않는다. 대화와 초안은 파일에 저장하지 않는다.

**지어내기 방지(2026-11-16)**: 작은 CPU 모델은 빈칸을 상상으로 채우는 경향이 있다(합성 예문 8번 중 6번이 요청에 없는 옷·소품·장소를 넣음, 지시문의 예시 단어가 그대로 나오기도 함). 그래서 ① 지시문에서 구체적인 물건 예시를 뺐고 ② 분량 목표를 60~150단어로 줄이고 자동 상세 보강을 끄고(요청에 `detail: true` 일 때만) ③ 요청·고정 칸·현재 내용에 없는 옷·장신구·머리 모양·색·소품·가구·장소 단어를 코드가 가장 작은 단위로 빼며 — 그 단어가 든 구("wearing a blue jacket", "holding a book and", 꾸밈말인 색 단어 하나) → 안 되면 절(쉼표·and·while 로 나뉜 부분) → 그래도 안 되면 문장 순, 장면의 동작이 다 사라지게 되면 원문을 남기고 표시 ④ 그 내역을 검토 결과에 '요청에 없는 내용'으로 보여 준다. 부분 수정은 원문을 건드리지 않고 표시만 한다. 단어 목록은 `prompt_helper.py` 의 `UNREQUESTED_TERMS`.

**장면 시각 재배분**: 작은 모델은 장면 시작 시각을 앞쪽에 몰아 넣는다(실측 예: 5초 영상에 0/1.2/1.8초 → 끄덕이기 두 번 1.2초, 웃음 0.6초, 마지막 동작만 3.2초). 새 초안은 코드가 장면 순서·문장은 그대로 두고 시각만 다시 나눈다: 몫 = 절반은 균등 + 절반은 동작 설명 길이(제곱근으로 완화), 장면마다 최소 0.8초(`spread_times`). 같은 예는 0/1.8/3.4초가 된다. 부분 수정에서는 사용자가 정한 시각을 바꾸지 않는다.

요약·장면별 동작·소리·음악만 생성하고 적용한다. ‘누가/무엇이 나오나’, ‘사진에서 그대로 유지할 것’, ‘장소·분위기·카메라’의 현재 값은 고정 조건으로 참고하며 변경하지 않는다. 새 초안에서는 외관을 `<Picture 1>` 그대로 유지하도록 첫 장면에 명시하고, 부분 수정에서는 기존 문구를 보존한다. 유지 조건의 기본값은 얼굴과 옷이며, 직접 입력하거나 저장한 값은 보존한다.

기존 도우미는 Qwen3.5-2B Q4_K_M과 llama.cpp b12374의 Windows CPU 전용 배포본을 사용한다. GPU 레이어 0, CPU 스레드 2개, 낮은 실행 우선순위, 동시 작성 1건으로 제한한다. 요청할 때만 모델을 실행하고 완료·취소·오류 후 프로세스를 종료한다. 준비 파일은 ComfyUI 폴더와 같은 위치의 `local-prompt-helper`에 있으며(`install_prompt_helper.py --comfy <ComfyUI 폴더>`, 생략하면 위치 규칙을 따름) 배포 주소·크기·SHA256은 `models.json`의 `prompt_helper`에 기록한다.

기존 2B는 RAM 여유가 4GiB 미만이면 시작하지 않고, 실행 중 2.5GiB 미만으로 줄면 도우미를 중지한다. 작성은 최대 7분(420초, 실행 준비 대기 최대 60초 별도)으로 제한한다. 영상 작업은 중지하지 않는다.

새 환경 설치:

```powershell
.\ComfyUI\.venv\Scripts\python.exe scripts/install_prompt_helper.py
```

검증은 임시 예시 문장과 모의 테스트로 진행한다. 실제 대기 작업이나 사진은 사용하지 않는다.
