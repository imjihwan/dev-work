# Grok 영상 제작 도우미

일반·갤러리·이어 만들기 화면에 대화형 제작 도우미가 붙는다. 넓은 PC 화면(1280px 이상)은 오른쪽 채팅 패널이 기본으로 열리고 작업 영역이 그 옆에 배치된다. 작은 화면에서는 오른쪽 아래 **제작 도우미 · Grok**을 눌러 넓은 채팅 화면으로 연다. 기존 2번의 프롬프트 작성 도우미는 그대로 사용할 수 있다. 공식 Grok CLI 계정 로그인은 공유하지만, 제작 도우미는 웹 조작과 앱 API 조회·실행까지 연결한다.

## 대화형 화면

질문과 답변은 말풍선으로 쌓이며, 변경안·변경 전후·실행 버튼은 해당 답변 바로 아래 카드에 표시한다. 실행 후에는 같은 카드에 전달/중단 상태가 남는다. 이어 질문하면 이전 제안은 읽기 전용으로 보관하고 최신 변경안만 실행할 수 있다.

PC의 **넓게**는 채팅 전체 화면, **분할 보기**는 작업 화면 옆 채팅으로 전환한다. **접기**로 대화를 유지한 채 작업 화면에 돌아간다. 열림/접힘만 브라우저에 저장하며 대화 원문은 새로 저장하지 않는다.

입력칸은 긴 글에 맞춰 높이가 늘어난다. PC에서는 Enter로 보내고 Shift+Enter로 줄바꿈한다. 터치 기기에서는 Enter로 줄바꿈하고 보내기 버튼을 사용한다. Ctrl/Command+Enter도 지원하며 한국어 조합 중 Enter는 전송하지 않는다. 응답 중에도 다음 요청을 작성할 수 있고, 전송 실패 시 작성 문구를 복원하되 이미 작성 중인 새 문구는 덮어쓰지 않는다.

이전 대화를 읽고 있으면 새 답변이 와도 스크롤을 강제로 내리지 않는다. **최신 대화로**를 눌러 이동할 수 있다. 새 대화는 채팅만 초기화한다. 채팅 입력 이벤트는 편집 화면과 이어 만들기 프로젝트의 입력 변경으로 처리하지 않는다.

## 사용

- `현재 최종 프롬프트와 설정을 설명해줘`
- `대기 2번 프롬프트를 가져와 현재 내용과 비교해줘`
- `대기 2번의 해당 문구만 바꿔줘. 나머지는 유지해줘`
- `길이를 5초로 바꾸고 현재 사진으로 1순위 대기열에 추가해줘`
- `실행 중인 건 유지하고 대기 3번만 취소해줘`
- `현재 작업을 같은 설정으로 다시 시작해줘`
- `저장된 설정 묶음의 이름을 바꿔줘`
- `갤러리에서 지정한 항목을 즐겨찾기에 넣어줘`

기본은 변경안 확인 후 **변경안 실행**이다. **명확하게 요청한 변경은 바로 실행**을 켜면, 모델이 직접 실행 요청으로 판정하고 코드의 명령문 검사도 통과한 경우 자동으로 실행한다. 이 선택은 브라우저·접속 주소별로 유지한다. 질문·설명·제안은 자동 실행하지 않는다. 기존 화면이 제공하는 확인 창·유효성 검사·파일 선택 절차는 유지한다.

대화는 최근 12개 메시지와 최신 미적용 변경안을 참고한다. 입력값이나 사진 선택이 바뀌면 기존 변경안의 실행을 중단하고 다시 요청하도록 안내한다. **새 대화**는 도우미의 맥락과 변경안을 지우며 입력·대기열·결과를 삭제하지 않는다. 도우미 요청 취소와 영상 작업 취소는 별개다.

## 접근 범위

현재 화면의 입력값, 자동·수동 **최종 프롬프트**, 선택 목록, 버튼, 체크 상태, 앱의 상태 메시지를 전달한다. 일반 화면과 현재 열린 같은 출처의 갤러리·이어 만들기 iframe을 함께 다룬다. 비밀번호와 파일 선택 경로는 제외한다. 파일 선택은 사용자가 직접 해야 한다.

대기열은 처음에는 순서·ID·상태·진행률만 전달한다. **대기 N번은 ComfyUI의 실제 대기 순서**를 뜻하며 완료 이력의 최근순과 다르다. 필요한 항목만 `queue_item`으로 조회해 ComfyUI에 들어가 있는 실제 최종 프롬프트와 기록된 입력·설정을 가져온다. 다른 항목도 요청에 필요한 경우 조회할 수 있다. 이력·갤러리·저장 설정·모델 카드·이어 만들기 프로젝트는 등록된 JSON API로 조회한다.

앱 API의 생성·우선추가·대기 수정·취소·재시작·설정 묶음·모델 조합·카드 설정·갤러리·편 생성/확정/병합·폴더 열기 기능을 호출할 수 있다. 현재 화면의 조작은 실제 입력 이벤트와 기존 버튼 동작을 사용한다. 사진·영상 표시·다운로드·파일 선택은 기존 웹 화면의 기능으로 요청하며, 미디어를 모델이 직접 시각적으로 분석하는 기능은 아니다.

사진·영상 바이트는 Grok에 전송하지 않는다. 저장 설정·프로젝트 API가 반환한 미디어 배열·경로·data URI도 전달 전에 제거한다. 현재 사진으로 생성하거나 사진이 포함된 설정 묶음을 저장할 때는 **브라우저가 기존 로컬 앱 API에만** 사진을 전달한다. Grok의 `"$current_settings"`·`"$current_generation"` 등의 이름을 브라우저에서 실행 직전에 실제 값으로 해석한다.

## 실행 방식

1. 브라우저가 입력·선택·버튼을 임시 참조 번호로 요약한다. 현재 최종 문구는 기존 자동 재조립 규칙으로 최신화한다.
2. Grok은 필요한 JSON 조회를 먼저 요청한다. 호스트가 허용된 앱 조회만 수행하고 결과를 다시 전달한다.
3. Grok은 설명과 변경안을 JSON으로 반환한다. 임의 셀렉터·스크립트·외부 URL·셸 명령은 실행하지 않는다.
4. 호스트가 실제 컨트롤, 정확한 원문, 선택 목록, 변경 대상과 현재 상태를 검사한다. 공통 대상·유지·카메라·원테이크 입력은 해당 항목 변경을 명시적으로 요청한 경우에만 수정한다. 최종 문구 직접 수정과 원본 텍스트 칸 수정은 한 변경안에서 섞지 않는다.
5. 실행 시 변경안·단계별로 한 번만 승인 기록을 잡는다. 중복 클릭·통신 결과 불명은 자동 재실행하지 않는다. 여러 단계 중 일부가 처리됐을 수 있으면 현재 앱 상태를 확인하도록 알린다.

지정 대기 항목의 문구 수정은 전체 문장을 다시 쓰기보다 **유일한 원문 구간을 정확히 교체**하는 전용 API를 우선한다. 조회 시 문구 해시를 기억하고, 적용 직전 문구와 전체 실행 그래프가 바뀌지 않았는지 검사한다. 수정할 노드는 기존 Director의 프롬프트 입력값뿐이다. 다른 설정·사진·순서·노드 연결은 유지한다. 변경된 최종 문구는 이력의 수동 최종 문구에도 함께 저장된다.

도우미 전용 대기 취소는 해당 ID만 제거하며, 조회 뒤 대기→실행으로 넘어간 항목을 임의로 중지하지 않는다. 현재 작업 중지·재시작은 조회한 실행 ID를 사용한다. 기존 웹의 `전체 중지`와 같은 기능은 앱 API로 대상 목록을 명확히 전달한다.

## 한계와 개인정보

- 이는 웹앱 전용 연결이다. Grok CLI의 파일·셸·웹 검색·스킬·MCP 도구는 계속 비활성화한다. 웹 기능의 PC 폴더 열기 외에 임의 파일 탐색이나 OS 명령을 제공하지 않는다.
- 큰 목록은 페이지 단위로 조회한다. 한 요청은 조회 단계 최대 5회, 한 조회 단계 4건, 변경 동작 8개로 제한한다. 대상이 많으면 범위를 나눠 요청한다.
- 브라우저의 파일 선택·자동 재생·클립보드 제한 등으로 사용자의 추가 조작이 필요할 수 있다. 버튼을 눌렀다는 응답은 영상 생성 완료를 뜻하지 않는다. 앱의 실제 진행 상태를 확인해야 한다.
- 모델은 자연어를 오해할 수 있다. 기본 확인 모드에서 변경 대상·내용을 먼저 검토할 수 있다.
- 전달한 입력·조회 문구와 대화의 외부 처리·기록은 Grok 계정/CLI 설정을 따른다. 전용 계정 폴더는 Git에서 제외한다. 자동 실행 설정은 브라우저에, 변경안과 실행 기록은 UI 서버 메모리에만 둔다(15분 만료). UI 서버 재시작 후 이전 변경안을 다시 실행하지 않는다.

## 검증

실제 사용자 작업·사진·결과물을 조회하거나 실제 작업을 제출하지 않았다. 가상 화면·대기열·프롬프트를 사용해 계획 검증, 조회 후 수정, 읽기/쓰기 분리, 정확한 부분 교체, 오래된 대상 거절, 중복 실행 방지, 로컬 사진 바인딩, 확인/자동 모드, 최종 문구 접근을 검사한다. 실제 Grok CLI 시험에서도 합성 문구와 모의 앱 API만 사용한다. 브라우저를 열거나 실제 미디어를 재생하는 검증은 하지 않는다.
