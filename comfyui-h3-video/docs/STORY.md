# 4편 이어 만들기

기존 화면 옆의 별도 탭을 사용한다. 공통 원본 사진·모델·LoRA·크기·24 FPS를 고정하고 약 5초씩 네 편을 생성해 약 20초로 병합한다. 이미지 전체를 미리 생성하는 단계는 없다.

1. 공통 사진·설정을 입력하고 네 편의 시나리오를 작성한다. 필요하면 연결 지점의 시작/끝 상태도 지정한다.
2. 각 편의 CPU 프롬프트 도우미로 초안을 작성하거나, 요청한 부분만 수정한다. 다른 편과 공통 조건은 변경하지 않는다. 결과를 확인하고 해당 편에 적용한 뒤 프로젝트를 저장한다.
3. 1번을 생성하고 사용자가 결과를 확인해 확정한다. 2번부터는 직전 확정 영상의 AV latent 끝 구간과 같은 원본 참조 사진을 함께 사용한다. 다음 편은 사용자가 진행 버튼을 눌러야 생성된다.
4. 네 편을 모두 확정하면 CPU로 병합한다. 전체 배경음악 파일은 선택 사항이며, 적용 시 각 편의 음악을 N/A로 두면 경계마다 음악이 다시 시작되는 문제를 피할 수 있다.

앞 편을 수정·재생성하면 후속 편의 확정을 해제하고 재검토를 표시한다. 공통 설정을 바꾸면 네 편 모두 재검토가 필요하다. 기존 영상은 자동으로 삭제하지 않는다. 생성 요청 ID를 먼저 저장해 화면 서버 재시작이나 응답 유실 때 같은 요청을 중복 제출하지 않는다. 프로젝트 코드로 다른 기기에서 같은 프로젝트를 불러올 수 있다.

프롬프트 도우미는 준비·이동·접촉·반응·마무리의 속도와 상태 변화를 자세히 작성한다. 짧은 새 초안은 동작과 시간표를 유지한 채 한 번 더 상세하게 보강한다. 부분 수정은 요청한 범위만 바꾼다. 작성·부분 수정 후 같은 CPU 모델로 별도 검토를 실행해 시간 부족, 물리적 충돌, 고정 조건 위반, 앞뒤 연결 문제와 수정 제안을 표시한다. 각 지적의 원문 근거를 함께 표시하며, 근거를 확인하지 못한 검토는 미완료로 표시한다. 숫자로 된 시간표는 코드로도 점검한다. `현재 편 동작·시간 검토`로 직접 고친 내용도 다시 검토할 수 있다. 검토는 원문을 자동 수정하지 않는다. 사진·실제 직전 영상을 읽지 않는 텍스트 검토이므로 실행 가능성과 결과 품질을 보장하지 않으며, 각 단계의 사용자 확인이 필요하다. 일반 영상 탭의 도우미에도 같은 상세 작성·검토가 적용된다.

첫 사진의 비율을 따라 영상용 크기로 한 번 맞춘다. 원본 사진의 큰 해상도를 무조건 사용하지 않는다. 네 편은 동일 크기로 생성하며, H3의 프레임 정렬로 생기는 미세한 길이 차이는 최종 병합에서 약 20초로 맞춘다. 같은 모델·LoRA가 일관성을 보장하는 것은 아니므로 각 단계의 사용자 확인을 유지한다.

원래 템플릿 파일은 변경하지 않는다. 별도 workflow adapter가 준비된 그래프의 복사본에 프로젝트 전용 Continuity 설정을 적용한다. 첫 편만 원본 사진의 시작 프레임을 고정하며, 후속 편의 시작 프레임에는 충돌하는 원본 사진 가이드를 중복 추가하지 않는다. 후속 편은 native AV tail guide로 움직임·소리를 이어받고 `use_references=true`로 원본 사진을 계속 참조한다. Segment Prepare/Decode/Publish로 새 구간만 출력해 누적 영상 전체를 매번 디코딩하지 않는다.

개인 작업이력·출력 폴더를 열거하거나 과거 결과를 자동 분석하지 않는다. 실행 중에는 이 프로젝트가 요청한 ID와 그 결과만 사용한다. 텍스트 프롬프트 작성은 기존 CPU 도우미로 처리한다. 개발 검증은 합성 이미지·가짜 대기열·합성 영상으로 수행하며 실제 개인 시나리오나 영상은 열지 않는다.
