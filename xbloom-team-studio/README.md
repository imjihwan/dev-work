# xBloom Team Studio

소스를 받아 실행하려면 [GitHub 소스 실행 안내](GITHUB-SETUP.md)를 참고하세요.

공유 xBloom Coffee 계정과 레시피를 관리하는 팀 웹사이트입니다. xBloom 로그인은 서버에서 처리하며 구성원은 xBloom 계정 정보 없이 같은 기기와 라이브러리를 봅니다.

## 시작

1. 사이트 소유자가 웹에 접속해 공유 공간을 시작합니다. 처음에는 소유자만 접근할 수 있습니다.
2. 연결 설정에서 xBloom 이메일·비밀번호를 한 번 입력합니다. 서버가 로그인하고, 인증 만료가 명확한 조회 오류에서는 자동 재인증합니다.
3. 가져오기로 생성·공유·제품 레시피 전체 페이지와 등록 기기·Auto Mode 설정을 불러옵니다. 일부 실패는 별도로 표시합니다.
4. 구성원 탭에 이메일과 편집자/조회 권한을 등록하고, 사이트 공유 설정에도 같은 사람의 접속 권한을 추가합니다. 이메일 발송은 앱에서 자동으로 하지 않습니다.
5. 레시피 초안을 저장한 후 다시 열어 xBloom에 전송합니다. 전송 전에 원본 변경을 비교하고 전송 후 재조회합니다. 공유/제품 레시피는 복사해 편집합니다.

## 구현

- ChatGPT 웹 로그인과 서버측 구성원 권한. xBloom 로그인과 별도입니다.
- D1에 공유 레시피·초안·revision·변경 이력을 영속 저장합니다.
- xBloom 이메일·비밀번호·세션은 서버에서 AES-256-GCM 암호화합니다. 암호화 키는 Sites 런타임 secret `XBLOOM_ENCRYPTION_KEY`로만 설정합니다. 브라우저나 로그에 반환하지 않습니다. 연결 해제로 삭제합니다.
- 쓰기를 직렬화하고 편집 revision을 검사합니다. 네트워크 오류로 쓰기 결과를 모르면 자동 재시도하지 않고 결과 미확인 상태로 보관합니다.
- 상태는 20초 간격으로 갱신합니다. 공식 앱 상태를 가져오는 작업은 가져오기 버튼으로 실행합니다.
- 기기가 여럿이면 가져오기 결과에서 공유 기기를 선택할 수 있습니다.
- 클라우드 A/B/C 프리셋을 조회하고 저장된 레시피로 교체할 수 있습니다.

## 실제 기기와 API 검증 범위

클라우드 프리셋 변경이 물리 기기 반영을 의미하지 않습니다. 기기 A/B/C 메모리에 적용하려면 공식 앱 또는 기기 근처의 별도 Bluetooth 브리지가 필요합니다. 이 웹은 커피 추출을 시작하거나 Bluetooth 하드웨어 명령을 실행하지 않습니다.

API는 xBloom Coffee 2.2.3 APK 정적 분석을 바탕으로 구현했습니다. 사용자 실제 계정·기기가 제공되지 않아 해당 계정으로 로그인/조회/등록·수정을 완료했다고 주장하지 않습니다. 계정 연결 후 서버 호환성 오류가 있으면 관리자에게 표시됩니다. 새 레시피의 숫자 범위는 앱에서 추가 검증할 수 있으며 모델/펌웨어별 범위는 달라질 수 있습니다.

기기 목록의 accessToken은 APK의 LoginActivity.loginSuccess → ServiceConfig.saveToken → MachineListForm 경로에 따라 로그인 응답의 projectToken을 사용합니다. 실제 계정에서의 성공 여부는 미검증입니다. 기기 조회 실패가 레시피 초안을 삭제하거나 가짜 기기를 생성하지 않습니다. 외부 앱과 서버 사이의 완전한 원자적 충돌 방지는 vendor API의 조건부 쓰기 기능이 확인되지 않아 보장하지 않습니다.

## 검증

- TypeScript 검사와 production build.
- 15개 프로토콜·편집 설정 테스트: OpenSSL과 RSA 결과 대조, 한글 분할, 페이지 처리, 쓰기 무재시도, 비밀값 오류 비노출, 레시피 비교·검증.
- 로컬 HTTP 검사: 공간 초기화, 초안 영속 저장, revision 충돌, 미연결 쓰기 차단, 구성원 권한 저장, 변경 이력, CSRF 차단, 익명 접근 차단.
- Chrome headless: 편집 화면 저장·재열기, 기기/설정 이동, 비밀번호 필드, 모바일 레이아웃. 로컬 테스트 데이터는 배포하지 않습니다.

개발: `npm run dev`. 빌드: `npm run build`. 프로토콜 테스트: `node --experimental-transform-types --test tests/protocol.test.ts`.

앱 편집 항목 대조와 수정 내역은 [EDITOR-PARITY.md](EDITOR-PARITY.md)에 기록했습니다. 커피·차 레시피의 누락 설정을 보완했고, 바이패스·그라인더 OFF·전후 진동·패턴·RT/BP·순서·복제의 저장 후 재조회까지 브라우저에서 검증했습니다.


## Bluetooth 직접 추출

사이드바 `Bluetooth 추출`에서 연결 → 저장된 레시피 선택 → 기기로 전송 → 준비 확인 → 추출 시작 순서로 사용합니다. 레시피 상세의 `이 레시피로 Bluetooth 추출`로도 이동합니다. 중지 버튼은 시작 응답 대기 중에도 사용할 수 있습니다. 현재는 xBloom Studio 커피 레시피를 지원하며, 차와 다른 모델은 전송 전에 차단합니다.

기기용 코드는 APK의 `GetRecipeCodeForm`/`tuGetRecipeCode.tuhtml` 경로로 서버에서 생성합니다. 계정 정보는 브라우저에 전달하지 않습니다. 서버는 구성원 편집 권한·레시피 revision·동기화 상태를 확인합니다. 원래 푸어 코드를 그대로 전송하므로 전후 진동·패턴·온도·유량을 임의로 단순화하지 않습니다. 바이패스·원두량·드리퍼 범위도 앱 순서로 전송합니다.

GATT 서비스 `0000e0ff-3c17-d293-8e48-14fe2e4da212`, 명령 `ffe1`(write without response), 알림 `ffe2`를 사용합니다. 세션/조회/바이패스/컵/레시피는 명령 8100/8022/8102/8104/8001 또는 8004입니다. 시작은 명령 8002를 한 번 보내고, 기기가 시작 확인 대기 상태를 보고하면서 자동 진행하지 않은 경우에만 40518을 한 번 보냅니다. 활성 추출 중지는 APK BrewerActivity의 4507, 준비 상태 취소는 40519입니다. 연결/전송은 추출을 시작하지 않습니다. 실패한 시작·중지는 자동 재시도하지 않습니다.

기기 알림은 길이와 CRC를 검증하고, MTU로 나뉜 알림을 조립합니다. 실제 armed 상태를 받아야 시작이 가능하며, 기기 상태 응답 전에는 시작/중지 성공을 표시하지 않습니다. 연결 끊김·레시피 revision 변경 시 기존 준비 상태로 다시 시작할 수 없습니다. 기기 상태와 무게는 현재 브라우저에서만 표시합니다. 다른 탭으로 이동해도 연결 컴포넌트를 유지하지만 새로고침·탭 닫기는 연결을 해제합니다. 연결 해제는 추출 중지가 아닙니다.

PC Chrome/Edge 또는 Android Chrome에서 HTTPS 사이트를 직접 열어 사용합니다. 앱 내 브라우저/권한 정책에서 Web Bluetooth가 없으면 안내하고 연결 버튼을 비활성화합니다. 실제 Bluetooth 장치 선택은 버튼 클릭으로만 열립니다. 브라우저가 지원해도 OS Bluetooth 권한과 기기 연결 상태에 따라 실패할 수 있습니다.

검증: 캡처 패킷과 바이트 대조, CRC, 분할 알림, 전송/시작 분리, 중복 시작 차단, 중지 우선 처리, 연결 끊김 검증. 브라우저 가상 GATT로 선택·연결·전송·시작·중지·화면 이동·모바일·조회 권한·미지원 브라우저를 검증합니다. 실제 사용자 기기 추출은 미검증이며, UI 검증 이미지는 가상 기기입니다.

참고: APK 2.2.3 `RecipeDetailActivity`, `BrewerActivity`, `BleCodeFactory`, `GetRecipeCodeTransfer`; https://github.com/brAzzi64/xbloom-ble 및 https://github.com/Janczykkkko/xbloom-ble-cloud 의 캡처 자료. Web Bluetooth 공식 문서: https://developer.chrome.com/docs/capabilities/bluetooth
