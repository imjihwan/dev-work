COMMAX Cloud 조명 통합 0.1.0

설치
1. ZIP을 풀고 custom_components/commax_cloud 폴더 전체를 HA의 설정 폴더에 복사합니다.
   최종 경로는 /config/custom_components/commax_cloud/manifest.json 이어야 합니다.
   이미 custom_components 폴더가 있으면 그 안에 commax_cloud 폴더만 추가합니다.
   configuration.yaml에 계정이나 플랫폼 설정을 추가할 필요는 없습니다.
2. Home Assistant를 재시작합니다.
3. 설정 → 기기 및 서비스 → 통합 구성요소 추가 → COMMAX Cloud를 선택합니다.
4. COMMAX IP Home IoT 앱에서 쓰는 ID와 비밀번호를 입력합니다.
   조명 목록 확인 후 light 엔티티가 자동으로 등록됩니다.
   현재 실계정에서는 일반 조명 8개가 조회되었습니다.

동작
- 일반 조명 켜기·끄기 및 상태 조회. 밝기·색온도 제어는 포함하지 않습니다.
- light.turn_on / light.turn_off / light.toggle 및 HA 대시보드에서 제어합니다.
- 계정에 등록된 모든 게이트웨이의 일반 조명 채널을 자동으로 검색합니다.
- 벽 스위치나 코맥스 앱에서 바꾼 상태는 기본 30초 이내 조회합니다.
- HA에서 명령을 보내면 1초 후 실제 서버 상태를 조회합니다.
  명령 접수 응답만으로 켜짐/꺼짐 상태를 추정하지 않습니다.
- 새 조명을 추가하면 다음 조회에서 엔티티를 추가합니다.
- 응답에 없거나 상태를 알 수 없는 조명은 사용할 수 없음으로 표시합니다.
- 명령을 직렬로 보내고 명령 간 간격을 최소 0.5초로 유지합니다.
- 네트워크 오류나 서버 장애로 실패한 제어 명령은 자동 재전송하지 않습니다.
- RS485 어댑터에 직접 데이터를 송신하지 않습니다.
- 콘센트, 일괄 소등, 가스, 난방, 환기는 이 버전에서 엔티티로 등록하지 않습니다.

토큰 자동 관리
- 로그인 응답의 expire_in을 초 단위로 계산합니다. 현재 계정에서는 259200초(3일)입니다.
- 만료 10분 전부터 리프레시 토큰으로 갱신합니다.
  유효기간이 매우 짧으면 갱신 여유를 그 기간의 10%로 줄입니다.
- 1분마다 별도로 토큰을 확인하므로 수동 조명 조작 없이도 갱신합니다.
- 갱신 후 새 접근/갱신 토큰과 만료 시각을 HA 설정에 저장합니다.
- HA가 재시작되어도 저장된 토큰과 동일한 단말 UUID를 재사용합니다.
- 리프레시 토큰이 거부되면 저장한 ID와 비밀번호로 1회 자동 로그인합니다.
- 서버 장애·통신 오류·요청 제한(429)은 잘못된 계정으로 취급하지 않습니다.
- 자동 로그인까지 거부되면 반복 로그인하지 않고 HA에서 재인증을 요청합니다.
- 재인증 화면에 새 비밀번호를 입력하면 저장된 계정 정보와 토큰을 바꾸고 통합을 다시 불러옵니다.
- 같은 계정을 유지해야 기존 기기 식별자와 엔티티가 보존됩니다.

저장 위치
ID, 비밀번호, 접근 토큰, 갱신 토큰, 만료 시각, 단말 UUID를 HA의 config entry에 저장합니다.
일반적으로 HA 설정 디렉터리의 .storage/core.config_entries에 들어갑니다.
이 통합이 별도로 암호화해 보관하는 것은 아니며 HA의 일반 설정 저장소를 사용합니다.
따라서 해당 파일과 백업에는 로그인 정보가 포함됩니다.
통합은 요청 URL·비밀번호·토큰·인증 응답 본문을 로그에 출력하지 않습니다.
배포 ZIP에는 실제 계정, 토큰, 시험 세션, 개인 기기 목록이 들어 있지 않습니다.

상태 조회 간격 변경
설정 → 기기 및 서비스 → COMMAX Cloud의 옵션에서 15~300초로 조절합니다.
토큰 갱신만으로 통합이 다시 로드되지는 않습니다.
상태 동기화는 HTTP polling 방식이며 MQTT 브로커나 MQTT 통합 설정은 필요하지 않습니다.

확인한 환경과 한계
- Home Assistant Core 2026.10.1 / Python 3.14.3에서 설정 흐름·조명 서비스·재인증·옵션·해제 테스트.
- 가상 API 서버에서 접근 토큰 만료, 리프레시 토큰 거부, 자동 로그인, 토큰 회전 및 중복 갱신 방지 검증.
- 실제 코맥스 서버에서 이 통합의 비동기 API로 토큰 갱신 및 조명 8개 조회 성공.
- 실제 안방 조명 ON/OFF는 같은 프로토콜의 앞선 시험 도구로 검증했습니다.
- 새 HA 통합으로 실제 집의 조명을 추가 조작하지는 않았습니다.
- 실제 리프레시 토큰 만료를 기다린 장기 운영은 아직 수행하지 않았습니다.
- 사용자의 운영 HA에 설치한 상태는 아닙니다. 설치 후 해당 HA 환경에서 최종 확인이 필요합니다.
- 비공개 앱 API를 재사용하므로 코맥스 서버 변경 시 수정이 필요할 수 있습니다.
- 인증서 검증은 HA의 기본 정책을 사용하며, 검증을 끄는 옵션을 제공하지 않습니다.

문제 해결
- 추가 목록에 보이지 않으면 폴더 경로를 확인하고 HA 전체를 재시작합니다.
- 코맥스 앱과 같은 계정으로 로그인합니다. 지원 대상은 com.commax.ipiot 앱의 프로토콜입니다.
- 비밀번호 변경 후 자동 로그인에 실패하면 HA의 재인증 안내를 사용합니다.
- 서버 장애 때 재인증 대신 사용할 수 없음으로 바뀌었다가 연결 복구 후 다시 조회합니다.
- 기존 RS485 기반 엔티티와 이름이 비슷할 수 있으니 자동화에 연결할 엔티티를 확인합니다.

개발·테스트
소스 폴더에서 Python 3.14 환경을 만든 뒤 다음 의존성을 설치합니다.
  python -m pip install homeassistant==2026.10.1 pytest pytest-asyncio ruff
  python -m pytest tests -q
  ruff check .
  ruff format --check .
테스트에는 가상 계정만 사용합니다. 테스트를 실행해도 실제 조명이 동작하지 않습니다.
